## 这一课做什么

### M1 拆成 6 课

原计划里 M1-4 是"全部主行动 + 待决策队列 + `getLegalMoves`"。写参考答案时发现，这样一课差不多是 M1-3 的三倍长，所以拆成三课：

| 课 | 内容 |
|---|---|
| **M1-4（本课）** | 指令的统一入口 `validateMove` / `applyMove`；待决策队列；自由行动（转换、牺牲能量）；主行动"改造并建造""升级建筑"；选宫殿板块；吸能；结束回合；开局的两种决策（选书的颜色、免费铲子）；开局结束后自动开始第 1 轮 |
| M1-5 | 学科：送学者、学科升级、能力板块（升学校和大学时拿）；推进航行和改造轨；能量行动、书本行动（含建桥、带铲子的建造）；pass |
| M1-6 | 一轮的完整流程（谁先 pass 谁下一轮先手、回合计分）；城市和城市板块；终局计分；`getLegalMoves` 和随机对局测试 |

做完 M1-4，引擎第一次能"玩起来"：开局 → 第 1 轮 → 轮流改造、建造、升级 → 邻居吸能。只是还不能 pass，所以一轮结束不了。

### 本课的内容

1. **接口升到第 4 版**：`TurnInfo` 多一个字段 `builtHexes`，记下本回合建过东西的格子
2. `reach.ts`、`turn.ts`：可达范围、行动前的通用检查、自动推进；测试工具 `fixtures.ts`
3. `build.ts`：改造并建造
4. `upgrade.ts`：升级建筑、选宫殿板块
5. `leech.ts`、`endturn.ts`：吸能、结束回合
6. `decide.ts`：回应决策
7. `move.ts`：统一入口，加上两种自由行动

## 第 1 步：接口变更 v4（20 分钟）

### 1.1 为什么要改接口

吸能（leech）是"有人新建或升级了建筑，旁边的其他玩家可以拿能量"。规则书说的是建完马上问邻居，我们改成**在建造者结束回合时**统一问。结果完全一样：建造者这一回合剩下的自由行动（转换资源之类）不会改变别人的能量碗和分数，别人在这期间也什么都做不了。但队列会干净很多：建造者自己引出的决策（比如选宫殿板块）先处理完，邻居的吸能再按顺序排进来，不会交错在一起。

这样引擎就要记住"这一回合在哪些格子上建过东西"，结束回合时才知道从哪里发起吸能。这个信息存在 `GameState.turn` 里最合适：它本来就是"当前这一回合"的状态，换人时整个换掉。

## 第 2 步：行动前的检查、测试工具（约 1.5 小时）

### 2.1 思路：一条指令是怎么被处理的

M1-3 的开局函数都是成对的：`validatePickSet` 回答"能不能做"，`applyPickSet` 负责"做"。这一课把所有指令都接到两个统一入口上（第 7 步写）：

```
服务端收到 { move, version }
  → validateMove(state, seat, move)   能做吗？不能就返回原因（RuleError）
  → applyMove(state, seat, move)      做，返回 { state, events }
```

`validateMove` 只是按指令种类分给各自的检查函数；每个检查函数开头都要先过一遍**通用检查**。通用检查分两层：

| 检查 | 自由行动（转换、牺牲能量） | 主行动（建造、升级……） |
|---|---|---|
| 游戏结束了 → `game-over` | ✓ | ✓ |
| 不在行动阶段 → `wrong-phase` | ✓ | ✓ |
| 不是你的回合 → `not-your-turn` | ✓ | ✓ |
| 还有决策没处理 → `decision-pending` | ✓ | ✓ |
| 这回合已经做过主行动 → `main-action-done` | | ✓ |

所以写成两个函数：`checkFreeAction` 做前四项，`checkMainAction` 先调用它、再加第五项。

**待决策队列。** `GameState.pending` 在 M1-3 已经用过了：开局时谁该选组合、谁该放工坊，都是排在里面的决策。这一课它要承担更多：升级宫殿后选板块、邻居吸能、开局选书的颜色……规矩只有三条：

1. 只能回应**排在第一个**的决策（`pending[0]`），而且只有 `pending[0].seat` 那个人能回应
2. 队列不空的时候，**谁都不能做别的**，当前回合的玩家也不行
3. 决策可能属于不是当前回合的人（吸能就是邻居来回应）

为什么用队列，不让几个邻居同时回应吸能？因为同一串指令必须重放出同一局游戏，"同时"在网络上没法保证先后。排成队列以后，顺序是确定的，界面也简单：永远只有一个人在做决定。代价是邻居要一个一个回应，多等几秒。

**`Applied`：执行结果。** M1-3 的 `applyPickSet` 只返回新的 `GameState`。从这一课起，执行函数返回 `{ state, events }`：新状态，加上这一步发生了什么（改造了哪一格、谁拿了多少能量）。事件给前端写日志、做动画用，引擎自己不读。

**可达范围。** M1-2 写了 `hexesInReach`（几个格子的可达范围合起来），它要的参数是地图、出发的格子、航行范围和桥。这一课要从 `GameState` 里把这些取出来：`reach.ts` 就是这层"接线"。航行范围是航行等级，拿着回合奖励板块"河边工坊"（`riverWorkshop`）时再 +1。

**自动推进。** M1-3 开局结束时，`phase` 是 `"income"`，开局要选的东西（荒地的书、沙漠的铲子）排在队列里。等它们都处理完，谁来开始第 1 轮？答案是 `advance`：第 7 步的 `applyMove` 每执行完一条指令都调用它，"在收入阶段、队列空了"就开始这一轮（所有人拿收入，轮到行动顺序第一个人）。这一课只有这一种推进；一轮结束进入下一轮在 M1-6 补上。

```ts
// 测试用的小工具：快速开出一局固定的游戏，并且可以随手改状态。
// 文件名不以 .test.ts 结尾，vitest 不会把它当成测试来跑，只给别的测试文件导入。
import {
    advance, applyInitialWorkshop, applyPickSet, createGame,
    type BuildingType, type GameState, type HexId, type PlayerState, type Seat, type SetupSet, type Terrain,
} from "../../src/aoi/index.ts";

/** 7 组固定组合：前 3 组是平原、沼泽、森林，都没有开局要选的东西 */
const SETS: Omit<SetupSet, "id" | "takenBy">[] = [
    { planning: "plains", faction: "philosophers", bonusTile: "coins6" },
    { planning: "swamp", faction: "navigators", bonusTile: "guildBuild" },
    { planning: "forest", faction: "blessed", bonusTile: "levelAction" },
    { planning: "lake", faction: "lizards", bonusTile: "scholarSend" },
    { planning: "desert", faction: "moles", bonusTile: "spadeAction" },
    { planning: "wasteland", faction: "goblins", bonusTile: "schoolsPass" },
    { planning: "mountain", faction: "omar", bonusTile: "bridgeAction" },
];

/**
 * 初始工坊放在哪：C6（平原）、C7（沼泽）、B6（森林）三格两两相邻，方便测吸能；
 * 每人另一个工坊放在远处。
 */
const START: Partial<Record<Terrain, HexId[]>> = {
    plains: ["C6", "E1"],
    swamp: ["C7", "A10"],
    forest: ["B6", "I1"],
    desert: ["D5", "A12"],
    wasteland: ["A6", "C1"],
};

/**
 * 开出一局 3 人游戏：选组合 → 放初始工坊 → 第 1 轮收入，停在行动阶段第一个人的回合。
 * picks 是依次选的组合编号；选了荒地（5）、沙漠（4）的话，停在开局决策那里
 */
export function readyGame(picks: number[] = [0, 1, 2]): GameState {
    const base = createGame({ playerCount: 3, mapId: "aoi-base", setupMode: { kind: "sets" } }, "m14");
    let state: GameState = {
        ...base,
        board: { ...base.board, setupSets: SETS.map((s, i) => ({ ...s, id: i, takenBy: null })) },
    };
    for (const id of picks) state = applyPickSet(state, state.pending[0].seat, id);
    const placed: Record<number, number> = {};
    while (state.phase === "setup") {
        const seat = state.pending[0].seat;
        const k = placed[seat] ?? 0;
        placed[seat] = k + 1;
        state = applyInitialWorkshop(state, seat, START[state.players[seat].homeTerrain]![k]);
    }
    return advance(state); // 开局没有要选的东西，就直接开始第 1 轮
}

/** 家园地形是 terrain 的那位玩家的座位号 */
export function seatOf(state: GameState, terrain: Terrain): Seat {
    return state.players.find((p) => p.homeTerrain === terrain)!.seat;
}

/** 改某位玩家的几个字段 */
export function withPlayer(state: GameState, seat: Seat, overrides: Partial<PlayerState>): GameState {
    return { ...state, players: state.players.map((p) => (p.seat === seat ? { ...p, ...overrides } : p)) };
}

/** 直接轮到某位玩家（跳过前面的人） */
export function turnOf(state: GameState, seat: Seat): GameState {
    return { ...state, turn: { seat, mainActionDone: false, builtHexes: [] } };
}

/** 直接在一格上放（或换成）某位玩家的建筑 */
export function withStructure(state: GameState, hex: HexId, owner: Seat, type: BuildingType): GameState {
    return {
        ...state,
        hexes: { ...state.hexes, [hex]: { ...state.hexes[hex], structure: { owner, type, neutral: false, annex: false, city: null } } },
    };
}
```

`readyGame` 把 7 组组合换成固定的（开局时本来是随机配的），这样测试里谁是什么派系、工坊在哪都是确定的。默认选前 3 组，开出来的地图是这样：

| 格子 | 地形 | 上面有什么 | 和谁相邻（只列本课测试用到的） |
|---|---|---|---|
| C6 | 平原 | 平原玩家的工坊 | C7、B6、D5、D6 |
| C7 | 沼泽 | 沼泽玩家的工坊 | C6、B6、D6；D7 是河 |
| B6 | 森林 | 森林玩家的工坊 | C6、C7 |
| D5 | 沙漠 | 空 | C6、D6 |
| D6 | 荒地 | 空 | C6、C7、D5 |
| D8 | 沼泽 | 空 | 隔着河格 D7 和 C7 相望 |
| E1 | 平原 | 平原玩家的另一个工坊 | 周围没有别人的建筑 |

C6、C7、B6 三格两两相邻，三位玩家挤在一起，测吸能和"升行会有优惠"都靠它们。

另外三个小工具：`withPlayer` 改某位玩家的几个字段（比如"给他 10 个工具"），`turnOf` 直接跳到某人的回合，`withStructure` 直接在一格上放建筑。它们都返回新的状态，不改原来的。

### 2.4 代码

新建 `packages/engine/src/aoi/reach.ts`：

```ts
// 和"某位玩家在地图上能够到哪里"有关的小工具。规则本身都在 map.ts 里，这里只是把 GameState 接上去。
import { MAPS } from "./content/maps.js";
import { hexesInReach, parseMap } from "./map.js";
import type { GameState, HexId, MapGeometry, PlayerState, Seat } from "./types.js";

/** 这局用的地图（解析好的） */
export function geometryOf(state: GameState): MapGeometry {
    return parseMap(MAPS[state.options.mapId]);
}

/** 某位玩家所有建筑所在的格子（中立建筑也算，它们也属于这位玩家） */
export function structuresOf(state: GameState, seat: Seat): HexId[] {
    return Object.keys(state.hexes).filter((id) => state.hexes[id].structure?.owner === seat);
}

/** 航行范围：航行等级，加上回合奖励板块"河边工坊"的 +1 */
export function reachRange(p: PlayerState): number {
    return p.sailing + (p.bonusTile === "riverWorkshop" ? 1 : 0);
}

/** 这一格在不在这位玩家的可达范围内 */
export function isInReach(state: GameState, seat: Seat, hex: HexId): boolean {
    const ownBridges = state.bridges.filter((b) => b.owner === seat);
    const reach = hexesInReach(geometryOf(state), structuresOf(state, seat), reachRange(state.players[seat]), ownBridges);
    return reach.includes(hex);
}
```

```ts
// 回合：行动前的通用检查、开始一轮、自动推进。
import { collectIncome } from "./income.js";
import type { GameEvent, GameState, RuleError, Seat } from "./types.js";

/** 执行一条指令或一个决策的结果：新状态，加上这一步发生了什么（给前端写日志、做动画） */
export interface Applied {
    state: GameState;
    events: GameEvent[];
}

/** 自由行动（转换、牺牲能量）之前的检查：行动阶段、轮到你、没有待处理的决策 */
export function checkFreeAction(state: GameState, seat: Seat): RuleError | null {
    if (state.phase === "ended") return "game-over";
    if (state.phase !== "actions" || state.turn === null) return "wrong-phase";
    if (state.turn.seat !== seat) return "not-your-turn";
    if (state.pending.length > 0) return "decision-pending";
    return null;
}

/** 主行动之前的检查：自由行动的检查，再加上"这回合还没做过主行动" */
export function checkMainAction(state: GameState, seat: Seat): RuleError | null {
    const error = checkFreeAction(state, seat);
    if (error !== null) return error;
    if (state.turn!.mainActionDone) return "main-action-done";
    return null;
}

/** 开始一轮的行动阶段：所有人拿收入，然后轮到行动顺序第一个人 */
export function startRound(state: GameState): GameState {
    const withIncome = collectIncome(state);
    return {
        ...withIncome,
        phase: "actions",
        turn: { seat: state.turnOrder[0], mainActionDone: false, builtHexes: [] },
    };
}

/**
 * 自动推进：没有人需要做决定的时候，游戏自己往下走。
 * 这一课只有一种情况：开局设置结束、开局的决策都处理完了，开始第 1 轮。
 * 一轮结束后进入下一轮，在 M1-6 补上。
 */
export function advance(state: GameState): GameState {
    if (state.phase === "income" && state.pending.length === 0) return startRound(state);
    return state;
}
```

## 第 3 步：改造并建造（约 2 小时）

### 3.1 规则

主行动"改造并建造"分两半，可以只做前一半：

**改造**（terraform）：选一格**没有建筑**、**在可达范围内**的格子，沿地形轮朝自己的家园地形改。地形轮是 平原 → 沼泽 → 湖泊 → 森林 → 山脉 → 荒地 → 沙漠 → 平原（首尾相接），两种地形之间隔几步就要几把铲子。M1-1 已经写好了 `terrainDistance`（要几铲）和 `terraformToward`（改几铲以后变成什么）。

- 铲子用工具买，每把几个工具看改造轨等级：3 / 2 / 1
- **可以只改一部分**：荒地离平原 2 铲，平原玩家可以只花 1 铲，把它改成沙漠
- 已经是家园地形的格子不用改造

**建造**：改完以后，这一格如果是家园地形，可以接着建一座工坊（1 工具 2 金币）。也可以不改造、直接在本来就是家园地形的格子上建。

什么都不做（0 铲、不建）不算主行动。

**判断的顺序**（`validateTerraformAndBuild`）：

1. 主行动的通用检查
2. 格子不存在 → `bad-move`；有建筑 → `hex-occupied`；够不着 → `not-in-reach`
3. 铲子数不是 0 到"要几铲"之间的整数 → `bad-move`；0 铲又不建 → `bad-move`
4. 要建，但改完还不是家园地形 → `not-home-terrain`；工坊用完了 → `limit-reached`
5. 付不起 → `insufficient-resources`

**执行**（`applyTerraformAndBuild`）：付钱，改地形，建工坊时规划板上少一座，主行动做过了；建了工坊的话，把格子记进 `builtHexes`（结束回合时从这里吸能）。事件按发生的顺序：改造、建造、付资源。

付资源的事件里，费用写成负数（`{ tools: -4, coins: -2 }`），表示"少了这么多"。为此在 `resources.ts` 里加一个小函数 `negateBundle`。

```ts
export function negateBundle(b: ResourceBundle): ResourceBundle {
    const result: ResourceBundle = {};
    for (const key of AMOUNT_KEYS) {
        const n = b[key];
        if (n) result[key] = -n;
    }
    if (b.books !== undefined) {
        const books: Partial<Record<BookColor, number>> = {};
        for (const [color, n] of Object.entries(b.books) as [BookColor, number][]) books[color] = -n;
        result.books = books;
    }
    return result;
```

```ts
// 主行动"改造并建造"：把一格的地形朝自己的家园地形改造，改成家园地形后可以建工坊。
import { BUILD_WORKSHOP_COST, TOOLS_PER_SPADE } from "./constants.js";
import { isInReach } from "./reach.js";
import { addBundles, negateBundle, payResources } from "./resources.js";
import { terrainDistance, terraformToward } from "./terrain.js";
import { checkMainAction, type Applied } from "./turn.js";
import type { GameEvent, GameState, HexId, PlayerState, ResourceBundle, RuleError, Seat, Structure } from "./types.js";

/** 用工具买 spades 把铲子要付多少：每把铲子的工具数看改造轨等级 */
export function spadeCost(p: PlayerState, spades: number): ResourceBundle {
    return spades === 0 ? {} : { tools: spades * TOOLS_PER_SPADE[p.terraforming] };
}

export function validateTerraformAndBuild(
    state: GameState, seat: Seat, hex: HexId, spades: number, build: boolean,
): RuleError | null {
    const error = checkMainAction(state, seat);
    if (error !== null) return error;
    const p = state.players[seat];
    const h = state.hexes[hex];
    if (h === undefined) return "bad-move";
    if (h.structure !== null) return "hex-occupied";
    if (!isInReach(state, seat, hex)) return "not-in-reach";

    const distance = terrainDistance(h.terrain, p.homeTerrain);
    if (!Number.isInteger(spades) || spades < 0 || spades > distance) return "bad-move";
    if (spades === 0 && !build) return "bad-move"; // 什么都不做
    if (build) {
        if (spades !== distance) return "not-home-terrain"; // 改造完还不是家园地形，不能建
        if (p.buildingsLeft.workshop === 0) return "limit-reached";
    }
    const cost = addBundles(spadeCost(p, spades), build ? BUILD_WORKSHOP_COST : {});
    if (payResources(p, cost) === null) return "insufficient-resources";
    return null;
}

/** 改造（可以只改一部分），并且可以选择建工坊。调用前先用 validateTerraformAndBuild 检查 */
export function applyTerraformAndBuild(
    state: GameState, seat: Seat, hex: HexId, spades: number, build: boolean,
): Applied {
    const p = state.players[seat];
    const h = state.hexes[hex];
    const cost = addBundles(spadeCost(p, spades), build ? BUILD_WORKSHOP_COST : {});
    const events: GameEvent[] = [];

    let player = payResources(p, cost)!;
    const terrain = terraformToward(h.terrain, p.homeTerrain, spades);
    if (terrain !== h.terrain) events.push({ type: "terraformed", seat, hex, from: h.terrain, to: terrain });
    if (build) {
        player = { ...player, buildingsLeft: { ...player.buildingsLeft, workshop: player.buildingsLeft.workshop - 1 } };
        events.push({ type: "built", seat, hex, structure: "workshop" });
    }
    events.push({ type: "resources", seat, delta: negateBundle(cost), reason: build ? "build" : "terraform" });

    const structure: Structure | null = build
        ? { owner: seat, type: "workshop", neutral: false, annex: false, city: null }
        : null;
    const turn = state.turn!;
    return {
        state: {
            ...state,
            hexes: { ...state.hexes, [hex]: { terrain, structure } },
            players: state.players.map((q) => (q.seat === seat ? player : q)),
            turn: { ...turn, mainActionDone: true, builtHexes: build ? [...turn.builtHexes, hex] : turn.builtHexes },
        },
        events,
    };
}
```

1. 为什么铲子数的检查（第 3 条）放在"够不着"（第 2 条）之后？
2. 平原玩家想在荒地 D6 上建工坊，一次行动能做到吗？要几个工具？
3. `validateTerraformAndBuild(game, plains, "D5", 2, false)` 为什么是 `bad-move`，而不是"多出来的那一铲浪费掉"？
4. 只改造、不建造的时候，为什么不把格子记进 `builtHexes`？

**答案**

1. 要先知道这一格存在、是空的，才能算"要几铲"（`h.terrain` 在格子不存在时会出错）。"够不着"放在前面，是因为它对玩家更有用：先告诉他"太远了"，比"铲子数不对"更说明问题。
2. 能。D6 离平原 2 铲，`spades: 2, build: true`：2 × 3 = 6 个工具，加上工坊的 1 个工具 2 金币，共 7 个工具 2 金币（改造轨 0 级时）。
3. 指令里的数字是玩家（前端）选的，多出来的铲子只可能是前端算错了或者有人乱发指令。直接拒绝，前端马上就会发现问题。规则上"多余的铲子作废"的情况发生在**免费铲子**上（比如能量行动给 2 铲但只用了 1 铲），那是第 6 步和 M1-5 的事。
4. 吸能只在"新建或升级建筑"时发生。改造地形不影响邻居。

## 第 4 步：升级建筑、选宫殿板块（约 1.5 小时）

### 4.1 规则

升级路线：

```
工坊 → 行会 → 学校 → 大学
          ↘ 宫殿
```

费用在 M1-1 的 `UPGRADE_COST` 里：行会 2 工具 6 金币，**旁边有别人的建筑**时只要 2 工具 3 金币（"旁边"包括用桥连着的）；学校 3 工具 5 金币；宫殿 4 工具 6 金币；大学 5 工具 8 金币。

升级时，新建筑从规划板上拿走，**旧建筑放回规划板**。规划板上的建筑盖着收入（M1-3 的 `incomeOf` 就是按空出来的格子算的）：工坊放回去，重新盖住一格工具收入；行会拿走，露出一格行会收入。所以升级不只是换了地图上的建筑，下一轮的收入也跟着变。

升级也算"建造"，邻居可以吸能，所以格子也要记进 `builtHexes`。

**判断的顺序**（`validateUpgrade`）：

1. 主行动的通用检查
2. 这里没有你的建筑 → `no-own-building`
3. 中立建筑，或者路线不对（比如工坊直接升学校）→ `cannot-upgrade`
4. 这种建筑用完了 → `limit-reached`
5. 付不起 → `insufficient-resources`

**宫殿板块。** 两种开局方式不一样：

- 固定组合开局：开局时不拿宫殿板块。**升级成宫殿时**，从场上的宫殿板块里选一个。这是一个决策，排进队列，叫 `palaceTile`
- 轮抽开局：宫殿板块在开局时就拿了（M1-3），升级成宫殿时不用再选

所以 `applyUpgrade` 里判断"升级成宫殿、而且手上还没有宫殿板块"，才排进决策。回应这个决策的函数 `validatePalaceTile` / `applyPalaceTile` 也写在这个文件里，第 6 步的 `decide.ts` 会调用它们。

升级成学校、大学时要拿能力板块，这一课先不做（M1-5）。

```ts
// 主行动"升级建筑"，以及升级成宫殿后的决策"选宫殿板块"。
import { UPGRADE_COST, UPGRADE_FROM } from "./constants.js";
import { isAdjacent } from "./map.js";
import { geometryOf } from "./reach.js";
import { negateBundle, payResources } from "./resources.js";
import { checkMainAction, type Applied } from "./turn.js";
import type {
    BuildingType, Decision, GameState, HexId, PalaceTileId, PlayerState, ResourceBundle, RuleError, Seat,
} from "./types.js";

/** 可以升级成的建筑：UPGRADE_FROM 的键，也就是 "guild" | "school" | "palace" | "university" */
export type UpgradeTarget = keyof typeof UPGRADE_FROM;

/** 升级的费用。工坊升行会时，旁边有别人的建筑就便宜一些 */
export function upgradeCost(state: GameState, seat: Seat, hex: HexId, to: UpgradeTarget): ResourceBundle {
    if (to !== "guild") return UPGRADE_COST[to];
    const geo = geometryOf(state);
    const neighbor = Object.entries(state.hexes).some(
        ([id, h]) => h.structure !== null && h.structure.owner !== seat && isAdjacent(geo, state.bridges, id, hex),
    );
    return neighbor ? UPGRADE_COST.guildWithNeighbor : UPGRADE_COST.guild;
}

export function validateUpgrade(state: GameState, seat: Seat, hex: HexId, to: UpgradeTarget): RuleError | null {
    const error = checkMainAction(state, seat);
    if (error !== null) return error;
    const s = state.hexes[hex]?.structure;
    if (s === undefined || s === null || s.owner !== seat) return "no-own-building";
    if (s.neutral || s.type !== UPGRADE_FROM[to]) return "cannot-upgrade";
    const p = state.players[seat];
    if (p.buildingsLeft[to] === 0) return "limit-reached";
    if (payResources(p, upgradeCost(state, seat, hex, to)) === null) return "insufficient-resources";
    return null;
}

/**
 * 升级：新建筑从规划板上拿走，旧建筑放回规划板。调用前先用 validateUpgrade 检查。
 * 升级成宫殿时，还没有宫殿板块的人（固定组合开局）要选一个。
 * 升级成学校、大学时拿能力板块，在 M1-5 加。
 */
export function applyUpgrade(state: GameState, seat: Seat, hex: HexId, to: UpgradeTarget): Applied {
    const p = state.players[seat];
    const h = state.hexes[hex];
    const from = h.structure!.type as BuildingType;
    const cost = upgradeCost(state, seat, hex, to);
    const paid = payResources(p, cost)!;
    const player: PlayerState = {
        ...paid,
        buildingsLeft: { ...paid.buildingsLeft, [to]: paid.buildingsLeft[to] - 1, [from]: paid.buildingsLeft[from] + 1 },
    };

    const pending: Decision[] = [...state.pending];
    if (to === "palace" && p.palaceTile === null) {
        pending.push({ id: `palaceTile-${state.version}`, seat, kind: "palaceTile", options: state.board.palaceTilesAvailable });
    }
    const turn = state.turn!;
    return {
        state: {
            ...state,
            hexes: { ...state.hexes, [hex]: { ...h, structure: { ...h.structure!, type: to } } },
            players: state.players.map((q) => (q.seat === seat ? player : q)),
            pending,
            turn: { ...turn, mainActionDone: true, builtHexes: [...turn.builtHexes, hex] },
        },
        events: [
            { type: "upgraded", seat, hex, from, to },
            { type: "resources", seat, delta: negateBundle(cost), reason: "upgrade" },
        ],
    };
}

// ---------- 决策：选宫殿板块 ----------

export function validatePalaceTile(state: GameState, seat: Seat, tile: PalaceTileId): RuleError | null {
    const d = state.pending[0];
    if (d === undefined || d.kind !== "palaceTile") return "wrong-phase";
    if (d.seat !== seat) return "not-your-decision";
    if (!d.options.includes(tile)) return "invalid-choice";
    return null;
}

/** 选宫殿板块：归这位玩家，从场上拿走。调用前先用 validatePalaceTile 检查 */
export function applyPalaceTile(state: GameState, seat: Seat, tile: PalaceTileId): Applied {
    const players = state.players.map((p) => (p.seat === seat ? { ...p, palaceTile: tile } : p));
    const palaceTilesAvailable = state.board.palaceTilesAvailable.filter((t) => t !== tile);
    return {
        state: { ...state, players, board: { ...state.board, palaceTilesAvailable }, pending: state.pending.slice(1) },
        events: [{ type: "tileTaken", seat, tile: String(tile), kind: "palace" }],
    };
}
```

## 第 5 步：吸能、结束回合（约 2 小时）

### 5.1 规则

**吸能**（leech，"拿邻居的能量"）：有人新建或升级了建筑以后，**每位其他玩家**看自己和这座建筑相邻的建筑（直接相邻或用桥连着），把它们的能量值加起来，就是能拿的能量。能量值：工坊 1，行会、学校 2，宫殿、大学 3（M1-1 的 `STRUCTURE_POWER`）。

拿 N 点能量要付 N − 1 分。M1-1 写好的 `leechOffer` 处理了两个例外：碗里装不下就少拿，分不够付也少拿。

几个设计决定：

- **什么时候问**：建造者结束回合时（第 1 步讲过原因）
- **问的顺序**：行动顺序里从建造者的下一位开始
- **只拿 1 点的自动接受**：1 点能量不用付分，没有理由拒绝，直接给，省得多问一次。这类吸能不进队列，只产生一个 `leech` 事件
- **其余的排进队列**，每人一个 `leech` 决策；接受就拿能量、付分，不接受什么都不变

**结束回合**（`endTurn`）：必须做过主行动（否则 `main-action-missing`），也要先过自由行动那层通用检查（比如有决策没处理完就不能结束）。结束时：

1. 本回合 `builtHexes` 里的每一格，依次向邻居发起吸能
2. 轮到行动顺序里下一个**还没 pass** 的人；其他人都 pass 了就还是自己；所有人都 pass 了，`turn` 变成 `null`（一轮结束，M1-6 接着处理）

吸能决策排进队列以后，下一个人虽然已经"轮到了"，但队列不空，他什么都做不了，要等邻居都回应完。

```ts
// 吸能：有人新建或升级了建筑，相邻的其他玩家可以获得能量，拿 N 点付 N-1 分。
import { structurePower } from "./city.js";
import { gainPower, leechOffer } from "./power.js";
import { isAdjacent } from "./map.js";
import { geometryOf } from "./reach.js";
import type { Applied } from "./turn.js";
import type { Decision, GameEvent, GameState, HexId, RuleError, Seat } from "./types.js";

/**
 * builder 在 hex 建了东西：其他每位玩家和 hex 相邻的建筑，能量值加起来是多少。
 * 新建筑自己的能量值不算。没有相邻建筑的玩家不出现在结果里。
 */
export function leechAmounts(state: GameState, builder: Seat, hex: HexId): { seat: Seat; power: number }[] {
    const geo = geometryOf(state);
    const totals = new Map<Seat, number>();
    for (const [id, h] of Object.entries(state.hexes)) {
        const s = h.structure;
        if (s === null || s.owner === builder || id === hex) continue;
        if (!isAdjacent(geo, state.bridges, id, hex)) continue;
        totals.set(s.owner, (totals.get(s.owner) ?? 0) + structurePower(s));
    }
    // 按行动顺序排，从建造者的下一位开始
    const order = state.turnOrder;
    const start = order.indexOf(builder);
    const result: { seat: Seat; power: number }[] = [];
    for (let i = 1; i < order.length; i++) {
        const seat = order[(start + i) % order.length];
        const power = totals.get(seat);
        if (power !== undefined) result.push({ seat, power });
    }
    return result;
}

/**
 * 从 hex 向邻居发起吸能。
 * 一点能量都拿不到的不发起；不用付分的（只拿 1 点）直接自动接受；其余排进待决策队列。
 */
export function leechDecisions(state: GameState, builder: Seat, hex: HexId): Applied {
    const events: GameEvent[] = [];
    const pending: Decision[] = [...state.pending];
    let players = state.players;
    for (const { seat, power: offered } of leechAmounts(state, builder, hex)) {
        const p = players[seat];
        const offer = leechOffer(offered, p.power, p.vp);
        if (offer === null) continue;
        if (offer.vpCost === 0) {
            players = players.map((q) => (q.seat === seat ? { ...q, power: gainPower(q.power, offer.power).bowls } : q));
            events.push({ type: "leech", seat, from: builder, power: offer.power, vpCost: 0, accepted: true });
        } else {
            pending.push({ id: `leech-${state.version}-${hex}-${seat}`, seat, kind: "leech", from: builder, ...offer });
        }
    }
    return { state: { ...state, players, pending }, events };
}

export function validateLeech(state: GameState, seat: Seat): RuleError | null {
    const d = state.pending[0];
    if (d === undefined || d.kind !== "leech") return "wrong-phase";
    if (d.seat !== seat) return "not-your-decision";
    return null;
}

/** 回应吸能：接受就拿能量、付分；不接受什么都不变。调用前先用 validateLeech 检查 */
export function applyLeech(state: GameState, seat: Seat, accept: boolean): Applied {
    const d = state.pending[0];
    if (d.kind !== "leech") throw new Error("队列第一个不是吸能");
    const players = accept
        ? state.players.map((p) => (p.seat === seat ? { ...p, power: gainPower(p.power, d.power).bowls, vp: p.vp - d.vpCost } : p))
        : state.players;
    return {
        state: { ...state, players, pending: state.pending.slice(1) },
        events: [{ type: "leech", seat, from: d.from, power: d.power, vpCost: d.vpCost, accepted: accept }],
    };
}
```

```ts
// 结束回合：本回合建过东西的格子向邻居发起吸能，然后轮到下一个人。
import { leechDecisions } from "./leech.js";
import { checkFreeAction, type Applied } from "./turn.js";
import type { GameEvent, GameState, RuleError, Seat } from "./types.js";

/** 行动顺序里，seat 之后下一个还没 pass 的人；所有人都 pass 了返回 null */
export function nextSeat(state: GameState, seat: Seat): Seat | null {
    const order = state.turnOrder;
    const start = order.indexOf(seat);
    for (let i = 1; i <= order.length; i++) {
        const s = order[(start + i) % order.length];
        if (!state.players[s].passed) return s;
    }
    return null;
}

export function validateEndTurn(state: GameState, seat: Seat): RuleError | null {
    const error = checkFreeAction(state, seat);
    if (error !== null) return error;
    if (!state.turn!.mainActionDone) return "main-action-missing";
    return null;
}

/** 结束回合。调用前先用 validateEndTurn 检查 */
export function applyEndTurn(state: GameState, seat: Seat): Applied {
    const events: GameEvent[] = [];
    let next = state;
    for (const hex of state.turn!.builtHexes) {
        const result = leechDecisions(next, seat, hex);
        next = result.state;
        events.push(...result.events);
    }
    const after = nextSeat(next, seat);
    if (after === null) return { state: { ...next, turn: null }, events }; // 所有人都 pass 了，M1-6 接着处理
    events.push({ type: "turn", seat: after });
    return { state: { ...next, turn: { seat: after, mainActionDone: false, builtHexes: [] } }, events };
}
```

### 5.4 新语法

| TypeScript | Python | 说明 |
|---|---|---|
| `new Map<Seat, number>()` | `{}`（`dict[int, int]`） | 键可以是任意类型的字典。`get` 取值（没有时是 `undefined`），`set` 存值 |
| `(totals.get(s.owner) ?? 0) + …` | `totals.get(owner, 0) + …` | `??`：左边是 `null` 或 `undefined` 时用右边 |
| `for (const { seat, power: offered } of …)` | `for x in …: seat, offered = x["seat"], x["power"]` | 解构时改名：取出 `power` 字段，放进叫 `offered` 的变量里（因为下面还要用 `offer.power`，免得混） |
| `{ id, seat, kind: "leech", from: builder, ...offer }` | `{"id": id, …, **offer}` | 把 `offer` 的 `power`、`vpCost` 两个字段展开进来 |
| `events.push(...result.events)` | `events.extend(result.events)` | 把数组展开成多个参数，一次加进去 |

### 5.5 读懂检查

1. 把 `leechAmounts` 里的 `s.owner === builder ||` 删掉，测试"建造者自己的建筑不算"不会变红。为什么？那这个条件还有必要留着吗？
2. `nextSeat` 的循环为什么是 `i <= order.length`（会转回自己），而不是 `i < order.length`？
3. 测试"碗里装不下全部能量"里，沼泽玩家的碗是 `[0, 1, 11]`，C7 是行会（能量 2）。最后为什么是自动接受、碗变成 `[0, 0, 12]`？
4. 结束回合时，`applyEndTurn` 先发起吸能，再换人。如果反过来先换人，结果有区别吗？

**答案**

1. 下面排顺序的循环从 `i = 1` 开始、到 `order.length - 1` 为止，正好跳过建造者自己，所以就算把自己的建筑加进 `totals`，也不会出现在结果里。留着条件是为了让第一段代码自己就是对的，不依赖第二段的写法。读代码的人看第一段就知道"自己的不算"，以后改了第二段也不会出错。
2. 其他人都 pass 了、只剩自己的时候，下一个还是自己，要接着行动直到自己也 pass。循环到 `i = order.length` 时 `(start + i) % length` 正好等于自己。测试"其他人都 pass 了：还是自己"就是测这个。
3. 碗 I 空，碗 II 只有 1 个，碗里最多只能再"流动"1 点（碗 II 的 1 个移到碗 III）。`leechOffer` 把 2 点减成 1 点，1 点不用付分，于是自动接受。
4. 没有区别。吸能只读建造者和邻居的状态，不读 `turn`。先吸能再换人是为了事件的顺序：日志里先显示"谁拿了能量"，再显示"轮到谁"，和桌上的顺序一样。

## 第 6 步：回应决策（约 1.5 小时）

### 6.1 思路

到这里已经有 7 种决策可以回应：M1-3 的选组合、轮抽、放初始工坊，本课的吸能、选宫殿板块，再加上开局要处理的两种：

- **选书的颜色**（`bookColor`）：荒地开局多 1 本"任选颜色"的书；以后收入里任选颜色的书也走这里。玩家给出 `{ 学科: 本数 }`，本数加起来要等于决策里的 `count`
- **免费铲子**（`spades`）：沙漠开局在所有建筑放完后有 1 把免费铲子，不能顺带建工坊。玩家给出用在哪一格，或者放弃（`{ skip: true }`）

`decide.ts` 是这些决策的统一入口，和第 7 步的 `move.ts` 一个思路：`validateDecide` 先做通用检查，再按 `choice.kind` 分给各自的函数。通用检查有三项：

1. 游戏结束了 → `game-over`
2. 队列第一个决策的 `id` 对不上 → `invalid-choice`。比如网络慢，玩家点了两下，第二下到服务端时第一个决策已经处理掉了，第二下回应的是"一个已经过去的决策"，要拒绝，不能把它当成对下一个决策的回答
3. `choice.kind` 和决策的种类对不上 → `bad-move`

"是不是你的决定"留给各自的函数查，因为每种决策都要查，而且各函数单独调用时（比如测试里）也要查。

**免费铲子的几种情况**（`validateSpades`）：

- 想顺带建工坊，但这个决策不允许 → `invalid-choice`；允许也先拒绝（`bad-move`），M1-5 写能量行动时再支持
- 格子不存在 → `bad-move`；有建筑 → `hex-occupied`
- 已经是家园地形 → `invalid-choice`（铲子没地方用）
- 够不着 → `not-in-reach`

铲子比一格需要的多时，多出来的排成一个新决策，可以用在下一格。这一课的沙漠铲子只有 1 把，不会出现这种情况，但写法已经通用了。

```ts
// 决策：玩家回应待决策队列里的第一个决定。按决策的种类分给各自的函数处理。
// 这里还放着两种开局时的决策：选书的颜色（荒地）、免费铲子（沙漠）。
import { DISCIPLINES } from "./constants.js";
import { applyLeech, validateLeech } from "./leech.js";
import { isInReach } from "./reach.js";
import {
    applyDraftPick, applyInitialWorkshop, applyPickSet,
    validateDraftPick, validateInitialWorkshop, validatePickSet,
} from "./setup.js";
import { terrainDistance, terraformToward } from "./terrain.js";
import type { Applied } from "./turn.js";
import { applyPalaceTile, validatePalaceTile } from "./upgrade.js";
import type { Decision, DecisionChoice, Discipline, GameState, HexId, RuleError, Seat } from "./types.js";

/** 回应决策之前的通用检查：游戏没结束、id 对得上（防止回应一个已经过去的决策）、种类对得上 */
export function validateDecide(state: GameState, seat: Seat, id: string, choice: DecisionChoice): RuleError | null {
    if (state.phase === "ended") return "game-over";
    const d = state.pending[0];
    if (d === undefined || d.id !== id) return "invalid-choice";
    if (d.kind !== choice.kind) return "bad-move";
    switch (choice.kind) {
        case "pickSet": return validatePickSet(state, seat, choice.set);
        case "draftPick": return validateDraftPick(state, seat, choice.item);
        case "initialWorkshop": return validateInitialWorkshop(state, seat, choice.hex);
        case "bookColor": return validateBookColor(state, seat, choice.books);
        case "leech": return validateLeech(state, seat);
        case "palaceTile": return validatePalaceTile(state, seat, choice.tile);
        case "spades":
            if ("skip" in choice) return d.seat === seat ? null : "not-your-decision";
            return validateSpades(state, seat, choice.hex, choice.build);
        // 下面几种在 M1-5、M1-6 实现
        case "bridge":
        case "scienceLevels":
        case "trackReward":
        case "competency":
        case "cityTile":
            return "bad-move";
        default: {
            const unhandled: never = choice;
            return unhandled;
        }
    }
}

/** 执行决策。调用前先用 validateDecide 检查 */
export function applyDecide(state: GameState, seat: Seat, choice: DecisionChoice): Applied {
    switch (choice.kind) {
        case "pickSet": return { state: applyPickSet(state, seat, choice.set), events: [] };
        case "draftPick": return { state: applyDraftPick(state, seat, choice.item), events: [] };
        case "initialWorkshop":
            return {
                state: applyInitialWorkshop(state, seat, choice.hex),
                events: [{ type: "built", seat, hex: choice.hex, structure: "workshop" }],
            };
        case "bookColor": return applyBookColor(state, seat, choice.books);
        case "leech": return applyLeech(state, seat, choice.accept);
        case "palaceTile": return applyPalaceTile(state, seat, choice.tile);
        case "spades": return "skip" in choice ? applySkipSpades(state) : applySpades(state, seat, choice.hex);
        default:
            throw new Error(`还没实现的决策：${choice.kind}`);
    }
}

    const d = state.pending[0];
    if (d === undefined || d.kind !== "bookColor") return "wrong-phase";
    if (d.seat !== seat) return "not-your-decision";
    let total = 0;
    for (const [color, n] of Object.entries(books)) {
        if (!(DISCIPLINES as readonly string[]).includes(color)) return "invalid-choice";
        if (!Number.isInteger(n) || n! < 0) return "invalid-choice";
        total += n!;
    }
    if (total !== d.count) return "invalid-choice";
    return null;
}

/** 按选的颜色把书加给玩家。调用前先用 validateBookColor 检查 */
export function applyBookColor(state: GameState, seat: Seat, books: Partial<Record<Discipline, number>>): Applied {
    const players = state.players.map((p) => {
        if (p.seat !== seat) return p;
        const next = { ...p.books };
        for (const d of DISCIPLINES) next[d] += books[d] ?? 0;
        return { ...p, books: next };
    });
    return {
        state: { ...state, players, pending: state.pending.slice(1) },
        events: [{ type: "resources", seat, delta: { books }, reason: "bookColor" }],
    };
}

// ---------- 免费铲子 ----------

/**
 * 免费铲子用在哪一格。这一课只处理不能顺带建工坊的情况（沙漠开局的铲子）；
 * 能顺带建工坊、铲子不够时用工具补的情况，M1-5 写能量行动时再加。
 */
export function validateSpades(state: GameState, seat: Seat, hex: HexId, build: boolean): RuleError | null {
    const d = state.pending[0];
    if (d === undefined || d.kind !== "spades") return "wrong-phase";
    if (d.seat !== seat) return "not-your-decision";
    if (build && !d.canBuild) return "invalid-choice";
    if (build) return "bad-move"; // M1-5 再支持
    const h = state.hexes[hex];
    if (h === undefined) return "bad-move";
    if (h.structure !== null) return "hex-occupied";
    if (h.terrain === state.players[seat].homeTerrain) return "invalid-choice"; // 已经是家园地形，铲子没地方用
    if (!isInReach(state, seat, hex)) return "not-in-reach";
    return null;
}

/** 在 hex 用免费铲子。一格用不完的铲子（这一课不会出现）排成新的决策，留给下一格 */
export function applySpades(state: GameState, seat: Seat, hex: HexId): Applied {
    const d = state.pending[0];
    if (d.kind !== "spades") throw new Error("队列第一个不是免费铲子");
    const p = state.players[seat];
    const h = state.hexes[hex];
    const used = Math.min(d.spades, terrainDistance(h.terrain, p.homeTerrain));
    const terrain = terraformToward(h.terrain, p.homeTerrain, used);
    const rest = state.pending.slice(1);
    const left = d.spades - used;
    const pending: Decision[] = left > 0 ? [{ ...d, id: `${d.id}-rest`, spades: left }, ...rest] : rest;
    return {
        state: { ...state, hexes: { ...state.hexes, [hex]: { ...h, terrain } }, pending },
        events: [{ type: "terraformed", seat, hex, from: h.terrain, to: terrain }],
    };
}

/** 不用免费铲子（放弃） */
export function applySkipSpades(state: GameState): Applied {
    return { state: { ...state, pending: state.pending.slice(1) }, events: [] };
}
```

### 6.5 读懂检查

1. `applyDecide` 的 `default` 分支为什么是 `throw`，而不像 `validateDecide` 那样做穷尽检查？
2. `validateBookColor` 里为什么要检查"是不是学科"、"是不是非负整数"？前端不会发这种东西。
3. 开局时荒地玩家选完书的颜色，`applyDecide` 返回的 `phase` 是什么？什么时候才变成 `"actions"`？
4. 第 4 步的 `validatePalaceTile` 第一行检查了 `d.kind !== "palaceTile"`，可是 `validateDecide` 已经查过种类了。是不是多余？

**答案**

1. `validateDecide` 对没实现的决策返回 `bad-move`，服务端就不会调 `applyDecide`。走到 `default` 说明有人跳过了 `validate`，这是程序的 bug，应该马上报错，而不是悄悄返回一个状态。另外 `default` 里的 `choice` 不是 `never`（那 5 种没实现的还在），所以这里也没法做穷尽检查。
2. 前端不会，但服务端不能假设消息都来自我们的前端。任何人都能连上房间发消息，引擎是最后一道关。后端的 zod 只检查格式（是不是对象、字段类型对不对），"本数是不是负数"这种规则层面的事归引擎。
3. 还是 `"income"`。`applyDecide` 只处理决策本身；第 7 步的 `applyMove` 执行完以后调用 `advance`，那时队列空了，才开始第 1 轮、变成 `"actions"`。
4. 在 `decide` 的流程里是多余的，但这些函数也会被单独调用（测试里就是）。每个函数都自己把关，单独用的时候也不会出错。多查一次的成本几乎为零。

```ts
// 指令的统一入口：服务端收到一条指令，先 validateMove，通过了再 applyMove。
// 资源转换、牺牲能量这两种自由行动很短，也直接写在这里。
import { applyTerraformAndBuild, validateTerraformAndBuild } from "./build.js";
import { DISCIPLINES } from "./constants.js";
import { convert } from "./convert.js";
import { applyDecide, validateDecide } from "./decide.js";
import { applyEndTurn, validateEndTurn } from "./endturn.js";
import { sacrificePower } from "./power.js";
import { advance, checkFreeAction, type Applied } from "./turn.js";
import { applyUpgrade, validateUpgrade } from "./upgrade.js";
import type { GameState, Move, RuleError, Seat } from "./types.js";

/** 这条指令现在能不能执行？能返回 null，不能返回原因 */
export function validateMove(state: GameState, seat: Seat, move: Move): RuleError | null {
    switch (move.t) {
        case "convert": return validateConvert(state, seat, move);
        case "sacrificePower": return validateSacrifice(state, seat, move.times);
        case "terraformAndBuild": return validateTerraformAndBuild(state, seat, move.hex, move.spades, move.build);
        case "upgrade": return validateUpgrade(state, seat, move.hex, move.to);
        case "endTurn": return validateEndTurn(state, seat);
        case "decide": return validateDecide(state, seat, move.id, move.choice);
        // 下面几种主行动在 M1-5 实现
        case "advanceTrack":
        case "sendScholar":
        case "developInnovation":
        case "powerAction":
        case "bookAction":
        case "specialAction":
        case "pass":
            return "bad-move";
        default: {
            const unhandled: never = move;
            return unhandled;
        }
    }
}

/**
 * 执行指令。调用前必须先用 validateMove 检查。
 * 执行完以后自动推进（比如开局的决策都处理完了，就开始第 1 轮），再把 version 加 1
 */
export function applyMove(state: GameState, seat: Seat, move: Move): Applied {
    const result = dispatch(state, seat, move);
    return { state: { ...advance(result.state), version: state.version + 1 }, events: result.events };
}

function dispatch(state: GameState, seat: Seat, move: Move): Applied {
    switch (move.t) {
        case "convert": return applyConvert(state, seat, move);
        case "sacrificePower": return applySacrifice(state, seat, move.times);
        case "terraformAndBuild": return applyTerraformAndBuild(state, seat, move.hex, move.spades, move.build);
        case "upgrade": return applyUpgrade(state, seat, move.hex, move.to);
        case "endTurn": return applyEndTurn(state, seat);
        case "decide": return applyDecide(state, seat, move.choice);
        default:
            throw new Error(`还没实现的指令：${move.t}`);
    }
}

// ---------- 自由行动：资源转换、牺牲能量 ----------

type ConvertMove = Extract<Move, { t: "convert" }>;

function validateConvert(state: GameState, seat: Seat, move: ConvertMove): RuleError | null {
    const error = checkFreeAction(state, seat);
    if (error !== null) return error;
    if (!Number.isInteger(move.times) || move.times < 1) return "bad-move";
    const needsColor = move.conversion === "power5ToBook" || move.conversion === "bookToCoin";
    if (needsColor && (move.color === undefined || !DISCIPLINES.includes(move.color))) return "bad-move";
    if (convert(state.players[seat], move.conversion, move.times, move.color) === null) return "insufficient-resources";
    return null;
}

function applyConvert(state: GameState, seat: Seat, move: ConvertMove): Applied {
    const player = convert(state.players[seat], move.conversion, move.times, move.color)!;
    return {
        state: { ...state, players: state.players.map((p) => (p.seat === seat ? player : p)) },
        events: [],
    };
}

function validateSacrifice(state: GameState, seat: Seat, times: number): RuleError | null {
    const error = checkFreeAction(state, seat);
    if (error !== null) return error;
    if (!Number.isInteger(times) || times < 1) return "bad-move";
    if (sacrificePower(state.players[seat].power, times) === null) return "insufficient-power";
    return null;
}

function applySacrifice(state: GameState, seat: Seat, times: number): Applied {
    const players = state.players.map((p) =>
        p.seat === seat ? { ...p, power: sacrificePower(p.power, times)! } : p,
    );
    return { state: { ...state, players }, events: [] };
}
```
