```
│                                                  │  能量行动 ×6         │

│                                                  │  回合奖励板块         │
│ [虚线] 你能到达的空格…                              │  （内容多时这一栏自己滚）│
├────────┬───────┬───────┬────────┬──────────┬──────┴────────────────────┤
│ 小唐    │ 资源   │ 能量碗 │ 剩余建筑 │ 轨道与板块 │ 行动区                     │  玩家板
│ 27 分   │       │       │        │          │                           │
└────────┴───────┴───────┴────────┴──────────┴───────────────────────────┘
```

整页正好一屏，不滚动。用的是 CSS 网格（CSS Grid）的"区域命名"写法：

```css
.aoi-root {
    height: 100vh;
    display: grid;
    grid-template-columns: minmax(0, 1fr) 320px;
    grid-template-rows: auto minmax(0, 1fr) auto;
    grid-template-areas:
        "top    top"
        "map    side"
        "bottom bottom";
}
```

`grid-template-areas` 像画一张小地图：三行两列，`top` 占满第一行，地图和侧栏并排在中间，玩家板占满最后一行。每个区块只要写 `grid-area: map;` 这样一句就会落到对应位置。中间那行是 `minmax(0, 1fr)`，意思是"剩下多少高度都给它，但允许比内容矮"，地图就会跟着窗口大小自动缩放。

|---|---|---|

## 6. 关键代码讲解

### 6.1 `mapView.ts`：格子画在哪

**odd-r 尖顶六边形**（pointy-top hexagon）。设外接圆半径（中心到顶点）为 $R$，那么一个格子的宽度是

$$W = \sqrt{3}\,R$$

直观地说：尖顶六边形左右两条竖边之间的距离，比"中心到顶点"的 2 倍略小，正好是 $\sqrt{3} \approx 1.73$ 倍。

第 `row` 行、第 `col` 列的格子，中心坐标是

$$x = W \cdot \left(\text{col} + 0.5 + 0.5 \cdot (\text{row} \bmod 2)\right), \qquad y = R + 1.5R \cdot \text{row}$$

两条规律就能记住这个公式：

- **横向**：同一行相邻两格的中心正好差一个格宽 $W$；奇数行（B、D、F…）整体右移半格，所以多加 $0.5W$。`row % 2` 在偶数行是 0、奇数行是 1，正好当开关用
- **纵向**：上下两行不是差 $2R$，而是差 $1.5R$，因为下一行的尖顶插进了上一行两个格子之间的缝里

```ts
export function hexCenter(row: number, col: number): { x: number; y: number } {
    return {
        x: PAD + HEX_W * (col + 0.5 + (row % 2) * 0.5),
        y: PAD + HEX_R + row * 1.5 * HEX_R,
    };
}
```

六个顶点：从中心出发，在 30°、90°、150°……330° 这 6 个方向上各走 $R$ 远。尖顶六边形的顶点正好在正上方（270°）和正下方（90°）。

```ts
for (let k = 0; k < 6; k++) {
    const a = (Math.PI / 180) * (30 + 60 * k);   // 角度换成弧度
    pts.push(`${cx + r * Math.cos(a)},${cy + r * Math.sin(a)}`);
}
```

SVG 的 y 轴是**朝下**的（和数学课上的坐标系相反），所以 90° 在下方。

**版图编号**（board label）：引擎的 `HexId` 连河流一起数（M1-2 定的），但版图上印的编号只数陆地格。`boardLabels` 按顺序把每行的陆地格重新数一遍：

```ts
for (const h of geo.hexes) {            // parseMap 给出的顺序：逐行、每行从左到右
    if (h.river) continue;              // 河流不占号
    countInRow[h.row] = (countInRow[h.row] ?? 0) + 1;
    labels[h.id] = String.fromCharCode(65 + h.row) + countInRow[h.row];
}
```

所以引擎的 `A3` 在界面上显示 `A2`。界面上一律显示版图编号（和朋友说"我建在 E2"时对得上实物），鼠标悬停的提示里附上引擎编号，方便对照日志。

**可达的空格**：

```ts
export function reachableEmpty(geo, state, seat): ReachableHex[] {
    const p = state.players[seat];
    const ownBridges = state.bridges.filter((b) => b.owner === seat);
    return hexesInReach(geo, ownedHexes(state, seat), p.sailing, ownBridges)
        .filter((id) => state.hexes[id] && state.hexes[id].structure === null)
        .map((id) => ({ id, spades: terrainDistance(state.hexes[id].terrain, p.homeTerrain) }));
}
```

规则判断全部交给你写的引擎函数，前端只做"筛掉有建筑的格子、再查一下要几铲"。这样规则只有一份，以后你改了 `hexesInReach`，地图上的虚线框会自动跟着变。

### 6.2 `HexMap.tsx`：SVG 分层

地图是一个 SVG（可缩放矢量图形，Scalable Vector Graphics）。SVG 里**后画的盖住先画的**，所以按从下到上的顺序分 5 层：

1. 河流
2. 陆地格（颜色 + 版图编号）
3. 可达范围的虚线框
4. 桥
5. 建筑徽章

几个细节：

- **`viewBox`**：`<svg viewBox="0 0 宽 高">` 定义了一套内部坐标。之后不管 SVG 在屏幕上被拉多大，里面的东西都按比例缩放。所以代码里的 `HEX_R = 40` 是内部坐标，不是像素，地图能随窗口大小变化
- **河流画大一点**（`HEX_R + 0.8`）：相邻两个河流格如果刚好贴边，抗锯齿会在中间留一道细白缝。各自多画 0.8，互相重叠一点就没缝了。陆地格反过来画小一点（`HEX_R - 1.4`），格子之间露出一道底色，看起来是一块块独立的地块
- **格子颜色读 `state.hexes`，不读地图**：地图数据是开局的样子，改造之后要以游戏状态为准
- **虚线框和文字颜色用 `inkOn(terrain)`**：沼泽、森林这类深色地块上用浅色，否则黑虚线在黑沼泽上看不见
- **建筑徽章**：建筑总是建在主人的家园地形上，所以"玩家色"和"格子色"永远一样。徽章靠一圈白边和格子分开
- **`pointer-events: none`**（在 CSS 里）：虚线框和徽章盖在格子上面，不加这个，鼠标停在格子中间时会被它们挡住，看不到格子的提示

### 6.3 对手视角：一个 `useState` 就够了

```tsx
const [viewed, setViewed] = useState<Seat>(mySeat);
const reach = useMemo(() => reachableEmpty(AOI_BASE, state, viewed), [state, viewed]);
```

- `useState`：React 的"组件自己的变量"。调用 `setViewed(2)` 后，React 会用新值重新渲染整个预览页
- `useMemo`：只有 `state` 或 `viewed` 变了才重新算可达范围，否则复用上次的结果。现在数据是假的、算得也快，用它主要是养成习惯：M2 接上服务器后，每次收到快照都会重新渲染，没必要每次都重算

顶栏的卡片是 `<button>`，带 `aria-pressed`，键盘 Tab 过去按回车也能切换。

### 6.4 一个 CSS 坑：优先级（specificity）

第一版截图里，学科轨道左边的刻度和格子错开了一行。原因是：

```css
.aoi-root ol { padding: 0; }        /* 清掉浏览器默认缩进 */
.sci-axis  { padding-top: 22px; }   /* 想让刻度往下挪，和轨道对齐 */
```

两条都作用在同一个 `<ol class="sci-axis">` 上。CSS 比"谁更具体"：第一条是"类名 + 标签名"，第二条只有"类名"，第一条更具体，赢了，`padding-top` 被清成 0。

解决办法是把清除默认样式的规则包进 `:where()`：

```css
.aoi-root :where(h3, p, ul, ol, dl, dd) { margin: 0; padding: 0; }
```

`:where()` 里面的东西不计入优先级，这条规则就变成"最弱的"，后面任何一条类名规则都能覆盖它。以后写"重置默认样式"的规则都可以这么写。

### 6.5 `resolveJsonModule`

TypeScript 默认不允许 `import def from "./xxx.json"`。在 `tsconfig.json` 里打开 `"resolveJsonModule": true` 后可以，而且 TypeScript 会根据 JSON 的内容推断类型（`rows` 是 `string[]`），传给 `parseMap` 时就能检查格式对不对。

地图 JSON 现在放在仓库根目录的 `tools/maps/`，前端用相对路径 `../../../../tools/maps/aoi-base.json` 引用。M1-3 你把它搬进引擎（`packages/engine/src/aoi/content/maps/`）后，我改成从引擎导入。

## 7. 界面设计的规则（在 01 的基础上补充）

1. **玩家的颜色 = 他家园地形的颜色**（不变）
2. **紫色只用于能量**（不变）
3. **河流用很浅的灰蓝色**，和饱和的"湖泊地形"蓝分得开
4. **地图是主角**：其余区域都是浅底色 + 细分隔线，不加阴影
5. **建筑徽章 = 玩家色圆 + 白边 + 一个字**，越高级的建筑圆越大
6. **字体只用系统自带的中文字体**（不变）

素材到位后，板块（宫殿、创新、能力、回合奖励、计分）会换成真实图片；缺图时自动退回现在的扁平样子。
