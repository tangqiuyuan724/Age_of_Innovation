# M0 教程：搭好联机骨架（零基础版）

> **适合谁**：会 Python，但没怎么用过 JavaScript / TypeScript / React / Node.js
> **预计用时**：约 2 周。第 1 周补基础（第 0、1 步），第 2 周动手（第 2–9 步）
> **已验证**：本教程的每条命令、每段代码，我都在 Node 22 + Colyseus 0.18.12 上完整跑过，包括两个浏览器联机对战和断网重连。照着做应该能一次跑通。

## 这一课要做出什么

一个能联机的小游戏 **"抢 21"**：

- 玩家轮流给总数加 1、2 或 3，谁正好加到 21 谁赢
- 用 5 位房间码开房、加入，最多 5 人
- 没轮到你时按钮是灰的；就算有人绕过前端硬发请求，服务器也会拒绝
- 断网后自动重连，其他人能看到你"离线"，网络恢复后接着玩

这个小游戏的结构，就是大创造时代最终版的**缩小版**。后面每个里程碑都只是把其中某一块换大：

| 这一课（抢 21） | 将来（大创造时代） | 会变吗 |
|---|---|---|
| `packages/engine`：约 60 行规则 | 几千行规则 | 内容变，结构不变 |
| 指令只有 `{ t: "add", n }` 一种 | 十几种指令 | 内容变 |
| `RoomMeta`：座位、在线状态、轮到谁 | 一样 | 基本不变 |
| 每步广播 `snapshot` 快照 | 一样 | 不变 |
| 服务器 5 步校验流程 | 一样 | 不变 |
| 前端 `net.ts` + Zustand store | 一样 | 不变 |

**做法建议**：配置文件可以复制粘贴；**规则引擎（第 4 步）和房间（第 5 步）的代码请自己一行行敲**，边敲边对照讲解。手敲能逼着你看清每个符号，这比读十遍都管用。

## 第 1 步：TypeScript 速成 + React 预习（约 3–5 天）

### 1.1 TypeScript 是什么

TypeScript（TS）= JavaScript（JS）+ 类型标注。和 Python 的 type hints 很像，区别在于 **TS 的类型检查是认真的**：类型对不上，VS Code 会标红，`tsc`（TypeScript 编译器）会报错。运行时 TS 会先被去掉类型、变回 JS 再执行。

### 1.2 一个文件看懂这个项目会用到的语法

在桌面新建文件夹 `ts-playground`，里面新建 `hello.ts`，**自己敲**下面的代码：

```ts
// 1. 类型标注
const target: number = 21;
let total = 0;            // 没写类型时，TS 会自己推断出 number
total += 3;

// 2. interface：描述一个对象长什么样
interface Player {
  nickname: string;
  seat: number;
  online: boolean;
}

// 3. 联合类型 + 字面量类型
type Phase = "waiting" | "playing" | "ended";
let phase: Phase = "waiting";

// 4. "可辨识联合"：用 t 字段区分不同的指令
type Move =
  | { t: "add"; n: number }
  | { t: "pass" };

function describe(move: Move): string {
  switch (move.t) {
    case "add":
      return `加 ${move.n}`;   // 这里 TS 知道 move 一定有 n
    case "pass":
      return "跳过";
  }
}

// 5. 箭头函数、数组方法
const players: Player[] = [
  { nickname: "小唐", seat: 0, online: true },
  { nickname: "朋友", seat: 1, online: false },
];
const onlineNames = players.filter((p) => p.online).map((p) => p.nickname);

// 6. 展开运算符：生成新对象，不改旧对象
const before = { total: 5, version: 1 };
const after = { ...before, total: 8, version: before.version + 1 };

// 7. 可能为空的值
function findWinner(list: Player[]): Player | null {
  return list.find((p) => p.seat === 99) ?? null; // 找不到就返回 null
}
const winner = findWinner(players);
const winnerName = winner?.nickname ?? "还没人赢";

// 8. async / await
function wait(ms: number): Promise<void> {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

async function main() {
  console.log(describe({ t: "add", n: 2 }), describe({ t: "pass" }));
  console.log(onlineNames, before, after, winnerName, phase, total, target);
  await wait(500);
  try {
    throw new Error("出错示例");
  } catch (e) {
    console.log("捕获到：", (e as Error).message);
  }
}

main();
```

在终端里运行（第一次会提示下载 tsx，输入 `y`）。不要用 VS Code 右上角 Code Runner 插件的"运行"按钮，它默认调用的 ts-node 已经不兼容新版 TypeScript，原因和改法见 9.3 常见问题：

```bash
cd ~/Desktop/ts-playground
npx tsx hello.ts
```

应该输出：

```
加 2 跳过
[ '小唐' ] { total: 5, version: 1 } { total: 8, version: 2 } 还没人赢 waiting 3 21
捕获到： 出错示例
```

逐条对照 Python：

| # | TypeScript | Python 里最接近的写法 | 说明 |
|---|---|---|---|
| 1 | `const x: number = 1` / `let y = 0` | `x: int = 1` | `const` 不能重新赋值，`let` 可以。**默认用 `const`** |
| 2 | `interface Player { … }` | `TypedDict` / `@dataclass` | 只描述形状，运行时不存在 |
| 3 | `type Phase = "waiting" \| "playing"` | `Literal["waiting", "playing"]` | 写错字符串会直接报错 |
| 4 | 可辨识联合（discriminated union） | 没有直接对应 | **这个项目最重要的语法**：将来十几种指令都这样定义。`switch (move.t)` 之后，TS 自动知道每个分支里 move 有哪些字段 |
| 5 | `(p) => p.online` | `lambda p: p["online"]` | 箭头函数 |
| 5 | `.filter(...).map(...)` | 列表推导式 `[p.nickname for p in players if p.online]` | |
| 6 | `{ ...before, total: 8 }` | `{**before, "total": 8}` | 不可变更新（immutable update），规则引擎全靠它 |
| 7 | `a?.b` | `a.b if a is not None else None` | 可选链（optional chaining） |
| 7 | `x ?? "默认"` | `x if x is not None else "默认"` | 空值合并（nullish coalescing） |
| 8 | `async` / `await` / `Promise` | `async def` / `await` / 协程 | 联网操作都是异步的 |
| 8 | `try { } catch (e) { }` | `try: … except Exception as e:` | |
| — | `===` | `==` | **JS 里永远用 `===`**，不要用 `==`（后者会做奇怪的类型转换） |
| — | `this` | `self` | 类里访问自己的字段，不用写在参数里 |
| — | `export` / `import { x } from "./a.ts"` | `from a import x` | 模块 |

### 1.3 感受类型检查的价值

在 `hello.ts` 最后加一行**故意写错**的代码：

```ts

```


## 第 2 步：生成项目骨架（约 1 小时）

### 2.1 一条命令生成项目

Colyseus 提供了脚手架（scaffold）工具，可以直接生成"回合制 + monorepo + 断线重连"的项目模板：

```bash
cd ~/Desktop/Age_of_Innovation
npm create colyseus-app@0.18.1 . -- --ts --preset turn-based --layout monorepo --name aoi --overwrite --yes
```

npm 问 `Ok to proceed? (y)` 时输入 `y`。逐项解释：

| 部分 | 含义 |
|---|---|
| `colyseus-app@0.18.1` | 固定脚手架版本，保证生成的文件和本教程一致 |
| `.` | 生成在当前文件夹 |
| `--` | 分隔符：后面的参数传给脚手架，而不是传给 npm |
| `--ts` | 用 TypeScript |
| `--preset turn-based` | 回合制模板 |
| `--layout monorepo` | 前端、后端分成两个包 |
| `--name aoi` | 包名前缀，生成 `@aoi/backend`、`@aoi/frontend` |
| `--overwrite` | 文件夹里已有 `docs/`，允许写入（**不会删除** docs，我测试过） |
| `--yes` | 其他问题都用默认值 |

它会自动运行 `npm install` 下载依赖，需要等几分钟。

### 2.2 跑起来看看

```bash
npm start
```

看到 `Listening on http://localhost:2567` 就成功了。浏览器打开 http://localhost:2567 是 Colyseus 自带的调试页面 Playground，可以随便点点。看完在终端按 `Ctrl + C` 停止服务器。

## 第 3 步：调整成三包结构（约 1 小时）

计划文档里的结构是 `apps/backend`、`apps/frontend`，再加一个**规则引擎包** `packages/engine`。规则引擎单独成包，服务端和前端都能用它。

### 3.1 删掉用不到的文件

```bash
rm pnpm-workspace.yaml
rm -r apps/backend/loadtest
```

（计划文档里写的是 pnpm。这里改用 npm workspaces：Node 自带，少装一个工具，效果一样。）

### 3.2 修改根目录 `package.json`

改成这样（`workspaces` 加上 `packages/*`，`scripts` 换成下面几个常用命令）：

```json
{
  "name": "aoi",
  "private": true,
  "workspaces": [
    "apps/*",
    "packages/*"
  ],
  "scripts": {
    "dev:server": "npm start -w apps/backend",
    "dev:client": "npm run dev -w apps/frontend",
    "start": "npm start -w apps/backend",
    "test": "npm test --workspaces --if-present",
    "typecheck": "npm run typecheck --workspaces --if-present"
  },
  "engines": {
    "node": ">= 22.0.0"
  },
  "version": "0.1.0"
}
```

- `-w apps/backend`：在指定子包里执行命令
- `--workspaces --if-present`：在所有子包里执行，没有这个命令的子包就跳过

### 3.3 创建引擎包

新建文件 `packages/engine/package.json`：

```json
{
  "name": "@aoi/engine",
  "version": "0.1.0",
  "private": true,
  "type": "module",
  "exports": {
    ".": "./src/index.ts"
  },
  "scripts": {
    "test": "vitest run",
    "test:watch": "vitest",
    "typecheck": "tsc --noEmit"
  }
}
```

- `"type": "module"`：使用现代的 `import/export` 语法
- `"exports"`：别人写 `import … from "@aoi/engine"` 时，实际加载 `src/index.ts`

新建 `packages/engine/tsconfig.json`：

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "strict": true,
    "noEmit": true,
    "skipLibCheck": true,
    "allowImportingTsExtensions": true
  },
  "include": ["src", "test"]
}
```

`"strict": true` 打开最严格的类型检查。规则引擎是最容易出 bug 的地方，越严越好。

新建 `packages/engine/src/index.ts`，先只写一行占位：

```ts
export {};
```

先在根目录运行一次 `npm install`，让 npm 认识这个新子包；然后再给引擎装测试工具：

```bash
npm install
npm install -D vitest typescript@5 -w packages/engine
```

> **顺序很重要**：如果跳过第一行的 `npm install`，第二行会只打印一句黄色警告 `@aoi/engine in filter set, but no workspace folder present`，然后**什么都没装**，很容易漏看。装完打开 `packages/engine/package.json`，确认多了 `devDependencies` 里的 `typescript` 和 `vitest`。

- `-D`：开发依赖（只在开发和测试时用，上线不需要）
- `typescript@5`：明确装 5.x。npm 上最新的是 TS 7（新的原生实现），项目里其他包用的是 5，保持一致避免奇怪问题

### 3.4 后端：换测试工具、加依赖

模板用的测试工具是 mocha，我们统一换成 Vitest（引擎也用它，一套就够）：

```bash
npm uninstall mocha @types/mocha @colyseus/loadtest rimraf -w apps/backend
npm install -D vitest -w apps/backend
npm install zod -w apps/backend
```

Zod 用来检查客户端发来的数据格式对不对。

打开 `apps/backend/package.json`，做两处修改：

1. `scripts` 改成：

   ```json
   "scripts": {
     "start": "tsx watch src/index.ts",
     "test": "vitest run",
     "test:watch": "vitest",
     "typecheck": "tsc --noEmit"
   },
   ```

   （`build` 和 `clean` 先删掉，M5 部署时再说。）

2. 在 `"dependencies"` 里**手动加一行** `"@aoi/engine": "*"`：

   ```json
   "dependencies": {
     "@aoi/engine": "*",
     "@colyseus/schema": "^5.0.14",
     …其余不变
   }
   ```

然后回到根目录执行一次：

```bash
npm install
```

**为什么引擎要手动加？** `@aoi/engine` 不在 npm 网站上，是我们自己的子包。npm 看到 workspaces 里有同名包，就会在 `node_modules/@aoi/engine` 放一个**快捷方式**（符号链接）指向 `packages/engine`。效果类似 Python 的 `pip install -e .`：改了引擎代码，后端立刻能用上。

### ✅ 检查点

```bash
ls -l node_modules/@aoi
```

应该看到三个箭头 `->`，分别指向 `apps/backend`、`apps/frontend`、`packages/engine`。

```bash
git add .
git commit -m "chore: 改成 backend/frontend/engine 三包结构"
```

## 第 4 步：规则引擎 + 单元测试（约 2 小时）

### 4.1 核心思想：规则 = 纯函数

**纯函数**（pure function）：同样的输入永远得到同样的输出，而且不修改输入、不联网、不读时间、不用随机数。

用 Python 来想：

```python
def apply_move(state: dict, seat: int, move: dict) -> dict:
    new_state = {**state, "total": state["total"] + move["n"]}
    return new_state   # 返回新的，不改旧的
```

这样做的好处在后面会一个个体现出来：

- 测试极其简单：给输入，比输出
- 服务端和前端用同一份代码，不会出现"前端以为能走、服务器不让走"
- 可以保存"初始状态 + 每一步指令"，随时重放出任意时刻的局面（存档、撤销、复盘都靠这个）

### 4.2 写规则

把 `packages/engine/src/index.ts` 改成下面这样。**自己敲**：

```ts
// 抢 21：玩家轮流给总数加 1~3，谁正好加到 21 谁赢。
// 这个文件里只有纯函数：不联网、不读时间、不改传进来的对象。

export type Seat = number;

export interface GameState {
  version: number;     // 每执行一步 +1
  total: number;       // 当前总数
  target: number;      // 目标数（默认 21）
  turnOrder: Seat[];   // 行动顺序
  activeIndex: number; // 轮到 turnOrder 里的第几个人
  winner: Seat | null; // 还没人赢时是 null
}

export type Move = { t: "add"; n: number };

export type RuleError = "game-over" | "not-your-turn" | "bad-amount" | "overshoot";

export type GameEvent =
  | { type: "added"; seat: Seat; n: number; total: number }
  | { type: "won"; seat: Seat };

export function createGame(seats: Seat[], target = 21): GameState {
  return { version: 0, total: 0, target, turnOrder: [...seats], activeIndex: 0, winner: null };
}

export function activeSeat(state: GameState): Seat | null {
  if (state.winner !== null) return null;
  return state.turnOrder[state.activeIndex];
}

export function validateMove(state: GameState, seat: Seat, move: Move): RuleError | null {
  if (state.winner !== null) return "game-over";
  if (activeSeat(state) !== seat) return "not-your-turn";
  if (!Number.isInteger(move.n) || move.n < 1 || move.n > 3) return "bad-amount";
  if (state.total + move.n > state.target) return "overshoot";
  return null;
}

export function applyMove(
  state: GameState,
  seat: Seat,
  move: Move,
): { state: GameState; events: GameEvent[] } {
  const error = validateMove(state, seat, move);
  if (error) throw new Error(`illegal move: ${error}`);

  const total = state.total + move.n;
  const events: GameEvent[] = [{ type: "added", seat, n: move.n, total }];
  const won = total === state.target;
  if (won) events.push({ type: "won", seat });

  const next: GameState = {
    ...state,
    version: state.version + 1,
    total,
    winner: won ? seat : null,
    activeIndex: won ? state.activeIndex : (state.activeIndex + 1) % state.turnOrder.length,
  };
  return { state: next, events };
}

export function getLegalMoves(state: GameState, seat: Seat): Move[] {
  const candidates: Move[] = [1, 2, 3].map((n) => ({ t: "add", n }));
  return candidates.filter((m) => validateMove(state, seat, m) === null);
}
```

逐段讲解：

- **`GameState`**：一局游戏的全部信息。注意 `version`：每走一步加 1，后面用来防止"基于旧局面的操作"。
- **`RuleError`**：所有可能的违规原因，用字面量联合类型列出来。服务器拒绝时就把它原样返回给前端。
- **`GameEvent`**：描述"发生了什么"。将来用来写游戏日志、播放动画。
- **`createGame(seats, target = 21)`**：`target = 21` 是默认参数，和 Python 一样。`[...seats]` 复制一份数组，避免和外面共用同一个数组。
- **`validateMove`**：只检查、不修改，返回错误原因或 `null`（合法）。
- **`applyMove`**：先校验（不合法就 `throw`，相当于 Python 的 `raise`），再用 `{ ...state, … }` 生成新状态。`%` 是取余，让行动顺序转圈。
- **`getLegalMoves`**：列出当前能做的所有动作。前端用它决定哪些按钮可以点。

> **将来的大创造时代引擎，就是这 5 个函数的放大版**：`createGame`、`validateMove`、`applyMove`、`getLegalMoves`，再加计分。

## 第 5 步：服务端房间（约 3 小时）

### 5.1 先理解 Colyseus 的几个概念

| 概念 | 是什么 |
|---|---|
| **Room**（房间） | 服务器上的一个对象，代表一局游戏。我们的 `GameRoom` 类就是房间的"模板"，每开一局创建一个实例 |
| **roomId** | 房间的 ID。我们把它改成 5 位房间码 |
| **sessionId** | 每个连接的 ID。同一个人刷新页面会得到新的 sessionId（M2 再处理） |
| **State / Schema** | 房间里会**自动同步**给所有客户端的数据。服务器改了它，客户端自动收到变化 |
| **消息 / 请求** | 客户端 → 服务器的通信。`send` 发了就不管；`request` 会等服务器回复"成功"或"拒绝（附原因）" |
| **broadcast** | 服务器 → 所有客户端发一条消息 |

房间的**生命周期**（lifecycle），按发生顺序：

```
onCreate   房间被创建（第一个人点"创建房间"时）
onJoin     有人加入
  … 收发消息 …
onDrop     有人非主动断线（网络抖动）→ 我们给他 60 秒重连时间
onReconnect  60 秒内回来了
onLeave    真正离开（主动离开，或重连超时）
onDispose  房间里没人了，房间被销毁
```

```ts
import { schema, t, type SchemaType } from "@colyseus/schema";

// 房间元数据：由 Colyseus 自动同步给所有客户端。
// 注意：这里不放游戏规则状态，规则状态在引擎里，以 JSON 快照下发。

export const PlayerMeta = schema({
  nickname: t.string().default(""),
  seat: t.uint8().default(0),
  connected: t.boolean().default(true),
});
export type PlayerMeta = SchemaType<typeof PlayerMeta>;

export const RoomMeta = schema({
  players: t.map(PlayerMeta),            // key = sessionId
  phase: t.string().default("waiting"),  // "waiting" | "playing" | "ended"
  hostSessionId: t.string().default(""),
  activeSeat: t.int8().default(-1),      // -1 = 没人在行动
  version: t.uint32().default(0),
});
export type RoomMeta = SchemaType<typeof RoomMeta>;
```

- `t.string()`、`t.uint8()`（0–255 的整数）、`t.boolean()`：字段类型。Schema 要精确知道类型，才能把数据压缩成很小的二进制增量发出去
- `t.map(PlayerMeta)`：字典，key 是字符串。类似 `dict[str, PlayerMeta]`
- `.default(…)`：默认值

**为什么只放元数据？** 计划文档 5.2 节解释过：游戏规则状态只在引擎里定义一次，以 JSON 快照整份发送。Schema 只放"谁在线、轮到谁"这类房间信息。

### 5.3 游戏房间

新建 `apps/backend/src/rooms/GameRoom.ts`。**这是本课最重要的文件，请自己敲**：

```ts
import { Room, Client, CloseCode, validate, type MessageContext } from "colyseus";
import { z } from "zod";
import {
  createGame, applyMove, validateMove, activeSeat,
  type GameState, type GameEvent,
} from "@aoi/engine";
import { RoomMeta, PlayerMeta } from "./schema/RoomMeta.js";

// 客户端加入时带的参数
const JoinOptions = z.object({
  nickname: z.string().trim().min(1).max(12),
});

// "move" 消息的格式
const MoveMessage = z.object({
  move: z.object({ t: z.literal("add"), n: z.number().int() }),
  version: z.number().int(),
});

// 服务器发给客户端的快照
export interface Snapshot {
  state: GameState;
  events: GameEvent[];
}

// 生成 5 位房间码（去掉了容易看错的 0/O/1/I）
const CODE_CHARS = "ABCDEFGHJKLMNPQRSTUVWXYZ23456789";
function makeRoomCode(): string {
  let code = "";
  for (let i = 0; i < 5; i++) code += CODE_CHARS[Math.floor(Math.random() * CODE_CHARS.length)];
  return code;
}

export class GameRoom extends Room<{ state: RoomMeta }> {
  maxClients = 5;
  state = new RoomMeta();

  private game: GameState | null = null;

  messages = {
    // 房主开始游戏
    start: (client: Client, _payload: unknown, ctx: MessageContext) => {
      if (client.sessionId !== this.state.hostSessionId) return ctx.reject("not-host");
      if (this.state.phase !== "waiting") return ctx.reject("already-started");
      if (this.state.players.size < 2) return ctx.reject("need-2-players");

      const seats = [...this.state.players.values()].map((p) => p.seat).sort((a, b) => a - b);
      this.game = createGame(seats);
      this.state.phase = "playing";
      this.lock(); // 开局后不再接受新玩家
      this.syncMeta();
      this.broadcastSnapshot([]);
      return { ok: true };
    },

    // 玩家行动：validate() 先用 zod 检查消息格式，格式不对直接拒绝
    move: validate(MoveMessage, (client, msg, ctx) => {
      if (!this.game) return ctx.reject("not-started");

      const player = this.state.players.get(client.sessionId);
      if (!player) return ctx.reject("not-seated");

      if (msg.version !== this.game.version) return ctx.reject("stale-version");

      const error = validateMove(this.game, player.seat, msg.move);
      if (error) return ctx.reject(error);

      const { state, events } = applyMove(this.game, player.seat, msg.move);
      this.game = state;
      if (state.winner !== null) this.state.phase = "ended";
      this.syncMeta();
      this.broadcastSnapshot(events);
      return { version: state.version };
    }),
  };

  onCreate() {
    this.roomId = makeRoomCode();
  }

  onJoin(client: Client, options: unknown) {
    const { nickname } = JoinOptions.parse(options); // 不合法会抛错，加入失败

    const player = new PlayerMeta();
    player.nickname = nickname;
    player.seat = this.nextFreeSeat();
    this.state.players.set(client.sessionId, player);

    if (!this.state.hostSessionId) this.state.hostSessionId = client.sessionId;
    console.log(`${nickname} 加入房间 ${this.roomId}，座位 ${player.seat}`);
  }

  // 非主动断线（网络抖动、合上笔记本……）
  onDrop(client: Client, code: CloseCode) {
    const player = this.state.players.get(client.sessionId);
    if (player) player.connected = false;
    this.allowReconnection(client, 60).catch(() => {}); // 给 60 秒重连
  }

  onReconnect(client: Client) {
    const player = this.state.players.get(client.sessionId);
    if (player) player.connected = true;
    // 断线期间错过的快照，重连后补发一次
    if (this.game) {
      const snapshot: Snapshot = { state: this.game, events: [] };
      client.send("snapshot", snapshot);
    }
  }

  // 真正离开（主动离开，或重连超时）
  onLeave(client: Client, code: CloseCode) {
    if (this.state.phase === "waiting") {
      this.state.players.delete(client.sessionId);
      if (this.state.hostSessionId === client.sessionId) {
        // 房主走了，把房主交给剩下的第一个人
        const [first] = this.state.players.keys();
        this.state.hostSessionId = first ?? "";
      }
    } else {
      // 游戏已开始：保留座位，只标记离线（M2 会加"凭座位令牌回到原座位"）
      const player = this.state.players.get(client.sessionId);
      if (player) player.connected = false;
    }
  }

  private nextFreeSeat(): number {
    const taken = new Set([...this.state.players.values()].map((p) => p.seat));
    let seat = 0;
    while (taken.has(seat)) seat++;
    return seat;
  }

  private syncMeta() {
    if (!this.game) return;
    this.state.version = this.game.version;
    this.state.activeSeat = activeSeat(this.game) ?? -1;
  }

  private broadcastSnapshot(events: GameEvent[]) {
    if (!this.game) return;
    const snapshot: Snapshot = { state: this.game, events };
    this.broadcast("snapshot", snapshot);
  }
}
```

逐段讲解：

**① Zod 格式定义**（文件开头）
`z.object({ nickname: z.string().trim().min(1).max(12) })` 描述"合法的加入参数长什么样"。`.parse(x)` 不合法就抛错，类似 Python 的 pydantic。**永远不要相信客户端发来的数据**：别人可以在浏览器控制台里发任何东西。

**② `class GameRoom extends Room<{ state: RoomMeta }>`**
继承 Colyseus 的 `Room`，尖括号里告诉 TS"我的同步状态是 RoomMeta 类型"。`private game` 是私有字段，不会同步给客户端，由我们手动以快照下发。

**③ `messages = { start: …, move: … }`**
客户端能发的消息都登记在这里。每个处理函数收到 `(client, 消息内容, ctx)`：

- `return ctx.reject("原因")`：拒绝，客户端的 `request` 会收到一个带 `reason` 的错误
- `return { … }`：成功，客户端收到这个返回值

**④ `move` 的处理流程**（最重要，将来大创造时代完全照搬）

```
① 格式校验    validate(MoveMessage, …)     消息结构不对 → 拒绝
② 游戏状态    !this.game                   还没开局 → 拒绝
③ 身份        players.get(sessionId)       不在座位上 → 拒绝
④ 版本号      msg.version !== game.version 基于旧局面的操作 → 拒绝
⑤ 规则校验    validateMove(...)            违规 → 拒绝（原因来自引擎）
⑥ 执行        applyMove(...)               得到新状态
⑦ 同步        syncMeta() + broadcastSnapshot()
```

第 ④ 步举个例子：你双击了 "+1"，两次请求都带 `version: 3`。第一次执行后 version 变成 4，第二次就会被拒绝，不会加两次。

**⑤ 生命周期方法**
`onDrop` 里调用 `allowReconnection(client, 60)` 保留座位 60 秒。`.catch(() => {})` 是防止服务器关闭时报一个无关紧要的错误。

**⑥ `this.lock()`**
锁住房间，匹配系统不会再把新玩家放进来。

**`.js` 后缀的小坑**：`import … from "./schema/RoomMeta.js"` 明明文件是 `.ts`，却要写 `.js`。这是 Node 的模块规则（运行时 .ts 会变成 .js），后端照模板这样写就行。引擎包里我们开了 `allowImportingTsExtensions`，可以直接写 `.ts`。

```ts
    // Bob 不是房主，不能开局
    await expect(bob.request("start")).rejects.toMatchObject({ reason: "not-host" });

    // 收集 Alice 收到的快照
    const snapshots: Snapshot[] = [];
    alice.onMessage("snapshot", (s: Snapshot) => snapshots.push(s));

    await alice.request("start");
    expect(room.state.phase).toBe("playing");
    expect(room.state.activeSeat).toBe(0);

    // 没轮到 Bob
    await expect(bob.request("move", { move: { t: "add", n: 1 }, version: 0 }))
      .rejects.toMatchObject({ reason: "not-your-turn" });

    // 格式错误（n 不是整数）会被 zod 拒绝
    await expect(alice.request("move", { move: { t: "add", n: 1.5 }, version: 0 })).rejects.toThrow();

    // Alice 合法行动
    const reply = await alice.request("move", { move: { t: "add", n: 2 }, version: 0 });
    expect(reply).toEqual({ version: 1 });
    expect(room.state.activeSeat).toBe(1);

    // 旧版本号的操作被拒绝（防止双击重复提交）
    await expect(bob.request("move", { move: { t: "add", n: 1 }, version: 0 }))
      .rejects.toMatchObject({ reason: "stale-version" });

    await room.waitForNextPatch();
    expect(snapshots.at(-1)?.state.total).toBe(2);
  });

  it("没有昵称不能加入", async () => {
    const room = await colyseus.createRoom("game", {});
    await expect(colyseus.connectTo(room, {})).rejects.toThrow();
  });
});
```

要点：

- `boot(appConfig)`：在测试里启动一个真的服务器；`cleanup()` 在每个测试前清空房间
- `colyseus.connectTo(room, { nickname: "Alice" })`：模拟一个客户端加入
- `await expect(promise).rejects.toMatchObject({ reason: "not-host" })`：断言这个请求**会被拒绝**，且原因是 `not-host`
- `room.state` 是服务端的状态，可以直接检查；`room.waitForNextPatch()` 等服务器把最新变化发出去

### 7.4 `net.ts`：联网 + 全局 store

新建 `apps/frontend/src/net.ts`：

```ts
// 所有和服务器打交道的代码都放在这里，React 组件只读 store、调用这里的函数。
import { ColyseusSDK, type Room } from "@colyseus/sdk";
import { create } from "zustand";
import type { default as server } from "@aoi/backend/app.config";
import type { GameRoom as ServerGameRoom, Snapshot } from "@aoi/backend/rooms/GameRoom";
import type { Move } from "@aoi/engine";

const SERVER_URL = "ws://localhost:2567";
const sdk = new ColyseusSDK<typeof server>(SERVER_URL);

type GameRoom = Room<ServerGameRoom>;
type MetaJSON = ReturnType<GameRoom["state"]["toJSON"]>;

interface Store {
  room: GameRoom | null;
  meta: MetaJSON | null;        // 房间元数据（Schema 同步过来的，转成普通对象）
  snapshot: Snapshot | null;    // 游戏状态快照
  reconnecting: boolean;
  error: string | null;
}

export const useStore = create<Store>(() => ({
  room: null, meta: null, snapshot: null, reconnecting: false, error: null,
}));

export async function createRoom(nickname: string) {
  await connect(() => sdk.create("game", { nickname }));
}

export async function joinRoom(code: string, nickname: string) {
  await connect(() => sdk.joinById<ServerGameRoom>(code.trim().toUpperCase(), { nickname }));
}

async function connect(join: () => Promise<GameRoom>) {
  useStore.setState({ error: null });
  try {
    const room = await join();
    attach(room);
  } catch (e) {
    useStore.setState({ error: "加入失败：" + (e instanceof Error ? e.message : String(e)) });
  }
}

// 加入成功后立刻注册所有监听，不要等 React 组件挂载，否则可能漏掉第一条消息
function attach(room: GameRoom) {
  // 注意：此刻 room.state 还是空的，第一份完整状态会在随后的 onStateChange 里到达
  useStore.setState({ room, meta: null, snapshot: null });

  room.onStateChange((state) => useStore.setState({ meta: state.toJSON() }));
  room.onMessage("snapshot", (snapshot: Snapshot) => useStore.setState({ snapshot }));
  room.onDrop(() => useStore.setState({ reconnecting: true }));
  room.onReconnect(() => useStore.setState({ reconnecting: false }));
  room.onLeave(() => useStore.setState({ room: null, meta: null, snapshot: null, reconnecting: false }));
}

export async function startGame() {
  await call((room) => room.request("start"));
}

export async function sendMove(move: Move) {
  const version = useStore.getState().snapshot?.state.version ?? 0;
  await call((room) => room.request("move", { move, version }));
}

export function leaveRoom() {
  void useStore.getState().room?.leave();
}

async function call(fn: (room: GameRoom) => Promise<unknown>) {
  const room = useStore.getState().room;
  if (!room) return;
  useStore.setState({ error: null });
  try {
    await fn(room);
  } catch (e: any) {
    useStore.setState({ error: errorText(e?.reason ?? e?.message) });
  }
}

const ERROR_TEXT: Record<string, string> = {
  "not-host": "只有房主可以开始",
  "already-started": "游戏已经开始了",
  "need-2-players": "至少需要 2 名玩家",
  "not-started": "游戏还没开始",
  "not-seated": "你不在座位上",
  "stale-version": "局面刚刚更新了，请再点一次",
  "game-over": "游戏已经结束",
  "not-your-turn": "还没轮到你",
  "bad-amount": "只能加 1～3",
  "overshoot": "不能超过 21",
};

function errorText(reason: string): string {
  return ERROR_TEXT[reason] ?? `出错了：${reason}`;
}
```

要点：

- **`import type { … } from "@aoi/backend/…"`**：只导入**类型**，不导入代码。这样前端写 `sdk.create("game", …)` 时，TS 会对照服务端的真实定义检查：房间名拼错、少传 nickname 都会标红。服务端代码本身不会被打包进浏览器。
- **Zustand 三个用法**：
  - `create<Store>(() => ({ 初始值 }))` 创建 store
  - 组件里 `useStore((s) => s.room)` 读取：值变了组件自动刷新
  - 组件外 `useStore.setState({ … })` 修改、`useStore.getState()` 读取
- **为什么在 `attach` 里立刻注册监听**：服务器可能在你加入后马上发消息。如果等 React 组件显示出来再注册，第一条消息可能就丢了。
- **`e?.reason`**：服务器 `ctx.reject("not-your-turn")` 的原因会出现在错误对象的 `reason` 字段里。

### 7.5 React 组件

先用 5 分钟把 React 的几个核心概念和井字棋教程对上：

| 概念 | 一句话 | 在下面代码里 |
|---|---|---|
| 组件（component） | 一个返回界面（JSX）的函数 | `function Lobby() { return <section>…</section> }` |
| JSX | 在 JS 里写类似 HTML 的标签；`{ }` 里放 JS 表达式 | `<b>{room.roomId}</b>` |
| state | 组件自己的、变化后会触发刷新的数据 | `const [nickname, setNickname] = useState("")` |

| 条件显示 | `条件 && <标签/>` 或 `条件 ? <A/> : <B/>` | `{room ? <GameView /> : <Lobby />}` |
| 列表 | 用 `.map` 生成多个标签，每个要有唯一 `key` | `players.map(([id, p]) => <li key={id}>…</li>)` |

新建 `apps/frontend/src/GameView.tsx`：

```tsx
import { getLegalMoves } from "@aoi/engine";
import { useStore, startGame, sendMove, leaveRoom } from "./net.ts";

export function GameView() {
  const room = useStore((s) => s.room)!;
  const meta = useStore((s) => s.meta);
  const snapshot = useStore((s) => s.snapshot);
  const reconnecting = useStore((s) => s.reconnecting);

  if (!meta) return <p>加载中…</p>;

  const players = Object.entries(meta.players).sort(([, a], [, b]) => a.seat - b.seat);
  const me = meta.players[room.sessionId];
  const isHost = meta.hostSessionId === room.sessionId;
  const game = snapshot?.state;
  // 用同一份规则引擎在本地算出"我现在能做什么"，按钮据此启用/禁用
  const legal = game && me ? getLegalMoves(game, me.seat) : [];

  return (
    <section>
      {reconnecting && <p className="banner">连接中断，正在重连…</p>}
      <p>房间码：<b>{room.roomId}</b>（发给朋友）</p>

      <h2>玩家</h2>
      <ul>
        {players.map(([id, p]) => (
          <li key={id}>
            {p.seat === meta.activeSeat ? "👉 " : ""}
            {p.nickname}
            {id === meta.hostSessionId ? "（房主）" : ""}
            {id === room.sessionId ? "（你）" : ""}
            {p.connected ? "" : " · 离线"}
          </li>
        ))}
      </ul>

      {meta.phase === "waiting" && (
        isHost
          ? <button onClick={() => startGame()}>开始游戏</button>
          : <p>等待房主开始…</p>
      )}

      {game && (
        <>
          <h2>当前总数：{game.total} / {game.target}</h2>
          {game.winner !== null ? (
            <p>🎉 {players.find(([, p]) => p.seat === game.winner)?.[1].nickname} 赢了！</p>
          ) : (
            <p>
              {[1, 2, 3].map((n) => (
                <button
                  key={n}
                  disabled={!legal.some((m) => m.n === n)}
                  onClick={() => sendMove({ t: "add", n })}
                >
                  +{n}
                </button>
              ))}
            </p>
          )}
        </>
      )}

      <p><button onClick={leaveRoom}>离开房间</button></p>
    </section>
  );
}
```

要点：

- `Object.entries(meta.players)` 把 `{ sessionId: 玩家 }` 变成 `[[sessionId, 玩家], …]`，类似 Python 的 `dict.items()`
- `.sort(([, a], [, b]) => a.seat - b.seat)`：按座位号排序。`[, a]` 是跳过第一个元素的解构
- **按钮的 `disabled` 由引擎的 `getLegalMoves` 决定**：前端和服务器用同一份规则，所以按钮能点 ⇔ 服务器会接受
- `<>…</>` 叫 Fragment，用来包住多个标签又不额外产生一个 HTML 元素

## 第 8 步：断线重连（约 1 小时）

代码其实已经写好了，这一步主要是**理解和亲手验证**。

### 8.1 断线 ≠ 离开

| 情况 | 服务端 | 客户端 |
|---|---|---|
| 网络抖动、合上笔记本 | `onDrop` → 标记离线，保留座位 60 秒 | `onDrop` → 显示"正在重连"横幅，SDK 自动重试 |
| 60 秒内回来 | `onReconnect` → 标记在线，补发快照 | `onReconnect` → 隐藏横幅 |
| 超过 60 秒，或点"离开房间" | `onLeave` | `onLeave` → 回到大厅 |

### 8.2 手动测试断网

1. 按第 7 步开好两个标签页，开局，各走一步
2. **在标签 B 里等至少 5 秒**（原因见下面的注意）
3. 标签 B 按 `F12` 打开开发者工具 → **Network（网络）** 面板 → 把限速下拉框（默认是 "No throttling"）改成 **Offline**
4. 观察：标签 B 出现黄色横幅"连接中断，正在重连…"；标签 A 的玩家列表里显示"朋友 · 离线"
5. 把 Offline 改回 No throttling，几秒后横幅消失，A 那边恢复在线
6. 轮到 B 时点按钮，确认还能正常玩

> **注意**：Colyseus SDK 有个规定，房间连上**满 5 秒**之后断线才会自动重连（这是我在验证时踩到的）。加入后马上断网，SDK 不会重试，会直接回到大厅。

| `Cannot find module '@aoi/engine'` | `package.json` 里忘了加 `"@aoi/engine": "*"`，或加完没在根目录 `npm install` |
| 前端显示"加入失败：…" | 服务器没开；房间码输错；房间已开局（被 lock 了） |
| `npm install -D … -w packages/engine` 只打印 `no workspace folder present` 警告 | 新子包还没注册，先在根目录跑一次 `npm install`，见 3.3 |
| 控制台警告 `onMessage() not registered for type 'snapshot'` | 收到了消息但没注册监听。检查 `attach` 里有没有 `room.onMessage("snapshot", …)` |
| 断网后没有重连，直接回到大厅 | 加入后不到 5 秒就断网了，见 8.2 的注意 |
| VS Code 里一片红，但命令行 typecheck 正常 | `Cmd + Shift + P` → `TypeScript: Restart TS Server` |
| 改了引擎代码，前端没变化 | Vite 一般会自动刷新；不行就手动刷新浏览器 |
