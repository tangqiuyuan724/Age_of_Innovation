## 3. 数据怎么流

```
现在（预览）：  mock.ts 的 MOCK_STATE ──▶ AoiPreview ──▶ 各个组件
M2 之后：       服务器快照 snapshot.state ──▶ （同一套组件）
                RoomMeta 里的昵称 ──────────▶ name(seat)
```

所有组件只接收一个 `GameState`（或其中的 `PlayerState`），外加一个把座位号变成昵称的函数 `name(seat)`。所以 M2 接入联机时，只要把 `MOCK_STATE` 换成 store 里的 `snapshot.state`，把 `MOCK_NAMES` 换成 `RoomMeta` 里的昵称，组件本身一行都不用改。

这也是接口先行的回报：我写这些组件时你还没写任何游戏逻辑，但因为大家都照 `GameState` 的类型来，将来能直接接上。

## 5. 关键代码讲解

### 5.1 `labels.ts`：用类型保证"每个代码都有中文"

```ts
export const RULE_ERROR_TEXT: Record<RuleError, string> = {
    "game-over": "游戏已经结束",
    "wrong-phase": "现在不能做这个",
    // ……19 个全写上
};
```

类型写成 `Record<RuleError, string>`，意思是 `RuleError` 里的**每一个**代码都必须有一条中文。如果你以后在 `RuleError` 里新增一个 `"no-bridges-left"`，前端这里会立刻报错 `Property '"no-bridges-left"' is missing`，提醒我补文案。`TERRAIN_NAME`、`DISCIPLINE_NAME` 等都是同样的写法。

`describeDecision` 用 `switch (d.kind)` 给每种决策写一句话，最后加了一个**穷尽检查**（exhaustiveness check）：

```ts
default: {
    // 穷尽检查：接口里新增了一种决策而这里没处理时，这一行会报类型错误
    const unhandled: never = d;
    return unhandled;
}
```

`never` 是"不可能存在的值"的类型。前面的 `case` 处理完所有 `kind` 后，走到 `default` 的 `d` 就只能是 `never`，赋值没问题；如果接口新增了一种决策（比如 `kind: "annex"`）而这里没写 `case`，`d` 就可能是这种新决策，赋给 `never` 会报 `Type '{ kind: "annex"; … }' is not assignable to type 'never'`。

为什么不直接靠"函数缺少返回值"的报错？我验证过：前端的 tsconfig 关掉了 `strictNullChecks`，这种情况下 TS 不会报"函数末尾没有返回值"。用 `never` 的写法不受这个设置影响。你在引擎里写 `applyMove` 处理各种 `Move` 时，也可以用同样的技巧。

### 5.2 `mock.ts`：带默认值的构造函数

```ts
function player(p: Partial<PlayerState> & Pick<PlayerState, "seat" | "faction" | "homeTerrain">): PlayerState {
    return {
        planning: p.homeTerrain,
        vp: STARTING_VP,
        coins: 0,
        // ……其余字段的默认值
        ...p,
    };
}
```

- `Partial<PlayerState>`：所有字段都可以不写
- `& Pick<PlayerState, "seat" | "faction" | "homeTerrain">`：但这三个必须写
- 函数体先写好默认值，最后 `...p` 用传进来的值覆盖

这样造一个玩家只需写和默认值不同的字段。M1-3 你写 `createGame` 时，造开局玩家也可以用这个思路。

### 5.3 `PowerBowls.tsx`：同一个组件，两种尺寸

我的玩家板上，碗里画出每一个能量指示物，下面写"可用几点、还能获得几点"；其他玩家的摘要里，碗缩小成只显示数字。靠一个 `compact` 参数切换：

```tsx
export function PowerBowls({ bowls, compact = false }: { bowls: Bowls; compact?: boolean }) { … }
```

碗 III（能直接花的能量）是实心紫色，一眼就能看出"现在能花多少"。

### 5.4 `App.tsx` + `useHash.ts`：最简单的"路由"

```tsx
const hash = useHash();
if (hash === "#aoi-preview") return <AoiPreview />;
```

`useHash` 读取网址 `#` 后面的部分，并在它变化时让组件重新渲染。现在只有两个页面，没必要引入路由库（router）；页面多起来以后再换。

注意 `useHash()` 放在 `if … return` **之前**调用。React 规定，组件每次渲染调用的 Hook（`useXxx` 函数）数量和顺序必须一样，所以不能把 Hook 写在条件返回之后。

## 6. 界面设计的几条规则

以后加新界面也按这几条来：

1. **玩家的颜色 = 他家园地形的颜色**。行动顺序、玩家板、学科轨道上的标记都用这个颜色，不另外分配"红黄蓝绿"。
2. **紫色只用于能量**：能量碗、能量行动的费用。看到紫色就是能量。
3. **数字是主角**：资源、分数用大号等宽数字，标签用小号灰字。不使用官方美术和图标。
4. **字体只用系统自带的中文字体**：标题用宋体，正文用苹方或微软雅黑。不用 Google Fonts，因为国内经常加载不出来。
