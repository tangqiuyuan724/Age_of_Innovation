## 第 1 步：理解"接口先行"（20 分钟）

我们现在是两个人同时开发：你写引擎和服务端，我写前端。如果各写各的，等到 M2 接在一起时，十有八九对不上：你的玩家资源叫 `coins`，我的叫 `money`；你的能量是数组，我以为是对象……

**接口先行**（contract first）的做法是：先把双方要交换的数据长什么样写成类型，双方都照这份类型写。TypeScript 会同时检查两边：你的引擎返回的 `GameState` 少一个字段会报错，我的前端读了一个不存在的字段也会报错。

请先读一遍 `docs/接口约定.md` 的第 1～4 节（分工、数据流、房间协议、引擎导出），第 5 节的类型下一步会逐段讲。

## 第 2 步：新建 `aoi` 模块（20 分钟）

### 2.1 为什么新开一个文件夹

M0 的房间和前端还在用抢 21 的引擎（`packages/engine/src/index.ts`），在 M2 之前不能动它。大创造时代的代码放进一个新文件夹 `src/aoi/`，通过一个新入口 `@aoi/engine/aoi` 导出，两套互不干扰。M2 接入真正的规则后，再把抢 21 删掉。

```bash
mkdir -p packages/engine/src/aoi packages/engine/test/aoi
```

### 2.2 增加子路径导出

打开 `packages/engine/package.json`，把 `exports` 改成：

```json
"exports": {
  ".": "./src/index.ts",
  "./aoi": "./src/aoi/index.ts"
},
```

意思是：

- `import … from "@aoi/engine"` → 加载 `src/index.ts`（抢 21）
- `import … from "@aoi/engine/aoi"` → 加载 `src/aoi/index.ts`（大创造时代）

这叫**子路径导出**（subpath exports），作用类似 Python 包里的子模块（`import aoi.engine`）。

### 2.3 一个重要约定：引擎内部 import 写 `.js`

`src/aoi/` 里的文件互相导入时，**后缀写 `.js`**：

```ts
import { TERRAIN_WHEEL } from "./constants.js";   // ✅ 文件其实是 constants.ts
```

原因：后端（`apps/backend`）导入 `@aoi/engine/aoi` 时，会按**后端的** tsconfig 检查这些文件。后端用的是 Node 的模块规则，只认 `.js` 后缀。写 `.js` 在引擎、后端、前端、Vitest 四个地方都能正确解析，写 `.ts` 只有其中一部分认。

**测试文件**不会被后端检查，所以 M0 那样写 `.ts` 也行，我们保持和 M0 一致：测试里写 `.ts`。

## 第 3 步：敲入接口类型（约 1.5 小时）

### 3.1 这个文件里的新语法

| 语法 | 例子 | Python 里最接近的 | 说明 |
|---|---|---|---|
| `Record<K, V>` | `Record<Discipline, number>` | `dict[Discipline, int]`，且**每个 key 都必须有** | 4 门学科一个都不能少 |
| `Partial<T>` | `Partial<Record<BookColor, number>>` | 所有字段都变成可选的 TypedDict（`total=False`） | 付书时只写用到的颜色，如 `{ law: 2 }` |
| 元组（tuple） | `type PowerBowls = [number, number, number]` | `tuple[int, int, int]` | 固定 3 个元素：碗 I、II、III |
| 可选字段 `?:` | `coins?: number` | `NotRequired[int]` | 可以不写 |
| 交叉类型 `&` | `DecisionBase & { kind: "leech"; … }` | 类继承：在 `DecisionBase` 的基础上再加字段 | 每种决策都有 `id` 和 `seat` |
| 对象联合（可辨识联合） | `Decision`、`Move`、`GameEvent` | 没有直接对应 | M0 学过：靠 `kind` / `t` / `type` 字段区分 |
| 数字和字面量的联合 | `space: number \| "return"` | `Union[int, Literal["return"]]` | 要么是格子下标，要么是字符串 `"return"` |
| 文档注释 `/** … */` | `/** 座位号：0 ~ 4 */` | docstring | VS Code 里鼠标悬停时会显示 |

### 3.2 读类型时要注意的几个设计

1. **`GameState.players[seat]`**：座位号就是数组下标。
2. **`hexes` 只存陆地格**：河流格不会变，放在地图定义里，不进状态。
3. **待决策 `pending`**：凡是"需要某个玩家做选择、而且可能不是当前行动的玩家"的情况（吸能、选城市板块、免费铲子用在哪……）都排进这个队列。前端只要看队列里有没有自己座位的决策，就知道该弹什么窗口。
4. **`Move` 里没有"开局选派系"**：开局的选择也是决策（`pickSet`、`initialWorkshop`），统一用 `{ t: "decide", … }` 提交，指令种类越少越好管。
5. **内容 id 现在是 `string`**：派系、板块的具体 id 要等 M1-3 整理内容数据表时才确定，到时再收紧成字面量联合类型。

## 第 5 步：地形轮（TDD，约 2 小时）

### 5.1 规则

7 种地形围成一个圈（地形轮），顺序是：

```
沙漠 → 平原 → 沼泽 → 湖泊 → 森林 → 山脉 → 荒地 → （回到沙漠）
desert  plains  swamp   lake   forest mountain wasteland
```

- 把一个格子改造（terraform）成你的家园地形，需要的**铲子数 = 两种地形在轮上的最短距离**。相邻 1 铲，隔一个 2 铲，最远 3 铲（7 个位置的圈，最远也只隔 3 步）。
- 可以**只改造一部分**：比如需要 3 铲但这次只用 1 铲，格子就沿最短方向朝你的家园地形变 1 步。

## 第 6 步：能量碗与吸能（TDD，约 3 小时）

### 6.1 规则

每位玩家有 3 个能量碗（power bowl），里面放能量指示物：

```
  碗 I        碗 II        碗 III
 ( 5 )  →   ( 7 )   →   ( 0 )      ← 开局默认 5/7/0
   ↑                        │
   └──────── 花费 ──────────┘
```

| 操作 | 规则 |
|---|---|
| **获得** N 点能量 | 一点一点来：碗 I 有指示物就把一个移到碗 II；碗 I 空了，就把碗 II 的一个移到碗 III；碗 I、II 都空了就拿不到了 |
| **最多还能获得多少** | 碗 I 里每个指示物能走 2 步（I→II→III），碗 II 里每个能走 1 步，所以是 `碗I × 2 + 碗II` |
| **花费** N 点能量 | 只能花碗 III 里的，花掉的回到碗 I。碗 III 不够就不能花 |
| **牺牲**（sacrifice） | 碗 II 至少有 2 个时：1 个移出游戏，1 个移到碗 III。每牺牲一次，总数少 1 |

**吸能**（leech，邻居建造时你获得能量）：

- 别人建造或升级后，你在新建筑旁边的建筑能量值加起来记为 N，你可以选择获得 N 点能量
- **要么全拿，要么不拿**。拿 N 点要付 **N − 1 分**（拿 1 点免费，拿 4 点付 3 分）
- 例外 a：碗装不下 N 点时，能拿多少拿多少，按**实际拿到的**付分
- 例外 b：分数不够付时，分数扣到 0 为止，拿到的能量 = **扣掉的分 + 1**
- 一点能量都拿不到时，就不发起吸能

### 6.2 测试（直接复制）

### 7.1 规则

终局有两种按名次给分：

| 计分项 | 第 1 名 | 第 2 名 | 第 3 名 |

| 区域（最大的相连建筑群） | 18 | 12 | 6 |
| 每门学科（等级） | 8 | 4 | 2 |

### A.1 `terrain.ts`

```ts
import { TERRAIN_WHEEL } from "./constants.js";
import type { Terrain } from "./types.js";

function wheelIndex(t: Terrain): number {
  return TERRAIN_WHEEL.indexOf(t);
}

/** 两种地形在地形轮上的最短距离 = 改造需要的铲子数（0~3） */
export function terrainDistance(a: Terrain, b: Terrain): number {
  const n = TERRAIN_WHEEL.length;
  const d = Math.abs(wheelIndex(a) - wheelIndex(b));
  return Math.min(d, n - d);
}

/** 从 from 出发，沿最短方向朝 home 改造 spades 步，最多改到 home 为止 */
export function terraformToward(from: Terrain, home: Terrain, spades: number): Terrain {
  const n = TERRAIN_WHEEL.length;
  const i = wheelIndex(from);
  const forward = (wheelIndex(home) - i + n) % n; // 顺着轮子走要几步
  const dir = forward <= n - forward ? 1 : -1;    // 哪个方向更近
  const steps = Math.min(spades, terrainDistance(from, home));
  return TERRAIN_WHEEL[(((i + dir * steps) % n) + n) % n];
}
```

### A.2 `power.ts`

```ts
import type { PowerBowls } from "./types.js";

/** 最多还能获得多少能量：碗 I 每个指示物能走 2 步，碗 II 每个能走 1 步 */
export function powerCapacity(bowls: PowerBowls): number {
  return bowls[0] * 2 + bowls[1];
}

/** 获得 n 点能量：先把碗 I 移到碗 II；碗 I 空了再把碗 II 移到碗 III */
export function gainPower(bowls: PowerBowls, n: number): { bowls: PowerBowls; gained: number } {
  let [b1, b2, b3] = bowls;
  let gained = 0;
  while (gained < n) {
    if (b1 > 0) { b1--; b2++; }
    else if (b2 > 0) { b2--; b3++; }
    else break;
    gained++;
  }
  return { bowls: [b1, b2, b3], gained };
}

/** 花费 n 点能量：只能从碗 III 花，花掉的回到碗 I。不够时返回 null */
export function spendPower(bowls: PowerBowls, n: number): PowerBowls | null {
  const [b1, b2, b3] = bowls;
  if (b3 < n) return null;
  return [b1 + n, b2, b3 - n];
}

/** 牺牲能量 times 次：每次碗 II 里 1 个移出游戏、1 个移到碗 III。碗 II 不够时返回 null */
export function sacrificePower(bowls: PowerBowls, times: number): PowerBowls | null {
  const [b1, b2, b3] = bowls;
  if (b2 < times * 2) return null;
  return [b1, b2 - times * 2, b3 + times];
}

/**
 * 吸能：邻居建造时，你相邻建筑的能量值合计为 offered。
 * 规则：要么全拿要么不拿，拿 N 点付 N-1 分；
 *  a. 碗不够装时，能拿多少拿多少，按实际拿到的付分；
 *  b. 分数不够付时，分数扣到 0 为止，拿到的能量 = 扣掉的分 + 1。
 * 一点能量都拿不到时返回 null（不发起吸能）。
 */
export function leechOffer(
  offered: number,
  bowls: PowerBowls,
  vp: number,
): { power: number; vpCost: number } | null {
  let power = Math.min(offered, powerCapacity(bowls)); // 例外 a
  if (power <= 0) return null;
  let vpCost = power - 1;
  if (vpCost > vp) {                                    // 例外 b
    vpCost = vp;
    power = vp + 1;
  }
  return { power, vpCost };
}
```

### A.3 `scoring.ts`

```ts
/**
 * 名次分：values 从高到低排名，第 1、2、3… 名分别得 points[0]、points[1]…。
 * 并列的人把他们占据的名次的分数加起来平分，向下取整。
 * 小于 minValue 的不参与排名（例如学科 0 级不得分）。
 */
export function rankPoints(values: number[], points: readonly number[], minValue = 1): number[] {
  const result = values.map(() => 0);
  const ranked = values
    .map((value, index) => ({ value, index }))
    .filter((x) => x.value >= minValue)
    .sort((a, b) => b.value - a.value);

  let place = 0;
  while (place < ranked.length && place < points.length) {
    const group = ranked.filter((x) => x.value === ranked[place].value);
    let pool = 0;
    for (let p = place; p < place + group.length && p < points.length; p++) pool += points[p];
    const share = Math.floor(pool / group.length);
    for (const x of group) result[x.index] = share;
    place += group.length;
  }
  return result;
}
```
