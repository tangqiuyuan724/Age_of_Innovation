## 第 1 步：接口变更 v3（30 分钟）

### 1.1 为什么要改接口

这次改了 4 处，原因各不相同：

**1. 派系和回合奖励板块有了正式编号。** M1-1 说过"内容 id 暂时是 `string`，等 M1-3 有了内容数据表再收紧"。现在数据有了，`FactionId` 和 `BonusTileId` 改成**字面量联合类型**（literal union），也就是"只能是这 12 个（或 10 个）字符串之一"。好处在第 4 步会看到：数据表写成 `Record<FactionId, …>` 后，少写一个派系 TypeScript 会直接报错。规划板每块对应一种家园地形，所以 `PlanningId` 直接等于 `Terrain`。

**2. 手上的书没有灰色。** M1-1 把灰色书定义成"可以当任意学科用的书"。对照配件后发现，游戏里的书只有 4 种颜色；配件上的灰色书图标表示"**任选颜色**"：

- 出现在**收益**里（例如回合奖励板块"收入 1 本书"），意思是你**马上**选一种颜色拿
- 出现在**费用**里（例如书本行动"花 2 本书"），意思是**任何颜色**都可以付

如果允许玩家手上存着灰色书、等用的时候再决定颜色，就比规则多了一份灵活性。比如研发创新要求特定颜色的书，有灰色书在手就能临时凑。所以改成：`PlayerState.books` 只有 4 种颜色；获得任选颜色的书时，产生一个新的决策 `bookColor`，让玩家选颜色。`BookColor` 类型保留，只在描述收益和费用时用。

**3. 两种开局方式。** 开房时选一种：

- **固定组合**（规则书的标准开局）：7 块规划板旁边各放 1 个随机派系、1 个随机回合奖励板块，组成 7 组，玩家轮流选一组。`BoardState.setupSets` 记录这 7 组。
- **轮抽**（draft）：规划板、派系、回合奖励板块、宫殿板块分开摆出来，玩家按蛇形顺序轮流拿，每次从自己还没拿过的类别里任选一样。`BoardState.draft` 记录摆出来的东西和每人拿到了什么。

开局方式写在 `SetupOptions.setupMode` 里。轮抽的顺序单独做成一个类型 `DraftOrder`，现在只有 `"snake"`（蛇形）一种，以后想加别的顺序（比如每圈都顺时针），在这个类型里加一个名字、在引擎里加一种排法就行，别的代码不用动。

轮抽时宫殿板块一开始就拿到手，所以 `PlayerState.palaceTile` 的含义要说清楚：宫殿建好之前，手上的宫殿板块不生效。

**4. 付书写清楚颜色。** `BookPayment`（付书时每种颜色各付几本）不再允许灰色。

## 第 2 步：随机数（30 分钟）

### 2.1 思路

开局有很多随机的事：谁先手、7 组派系怎么配、翻开哪 3 个书本行动……但我们的架构要求**同一串指令重放出同一局游戏**（M2 要靠这一点做断线恢复和撤销）。如果引擎里直接调用 `Math.random()`，每次重放结果都不一样。

解决办法是**伪随机数生成器**（pseudo-random number generator，PRNG）：给它一个起点（叫**种子**，seed），它按固定的算法算出一串"看起来随机"的数。同一个种子永远得到同一串数。

我们把生成器的**状态**（一个整数）存在 `GameState.rng` 里。每取一个随机数，就得到"随机数 + 新状态"，把新状态存回去。这和能量碗的写法一样：不改旧的，返回新的。

```ts
import { describe, it, expect } from "vitest";
import { nextRandom, randomInt, seedFromString, shuffle } from "../../src/aoi/index.ts";

describe("seedFromString", () => {
    it("同一个字符串得到同一个种子", () => {
        expect(seedFromString("room-ABCDE")).toBe(seedFromString("room-ABCDE"));
    });
    it("不同字符串得到不同种子", () => {
        expect(seedFromString("a")).not.toBe(seedFromString("b"));
    });
    it("种子是非负整数", () => {
        const s = seedFromString("任意中文也可以");
        expect(Number.isInteger(s)).toBe(true);
        expect(s).toBeGreaterThanOrEqual(0);
    });
});

describe("nextRandom", () => {
    it("结果在 [0, 1) 之间，并返回新状态", () => {
        let rng = seedFromString("x");
        for (let i = 0; i < 1000; i++) {
            const [r, next] = nextRandom(rng);
            expect(r).toBeGreaterThanOrEqual(0);
            expect(r).toBeLessThan(1);
            expect(next).not.toBe(rng);
            rng = next;
        }
    });
    it("同一个状态永远得到同一个结果", () => {
        expect(nextRandom(12345)).toEqual(nextRandom(12345));
    });
});

describe("randomInt", () => {
    it("结果在 0 ~ n-1，而且每个数出现的次数差不多", () => {
        const counts = [0, 0, 0, 0, 0, 0, 0];
        let rng = seedFromString("dice");
        for (let i = 0; i < 7000; i++) {
            let k: number;
            [k, rng] = randomInt(rng, 7);
            counts[k]++;
        }
        for (const c of counts) {
            expect(c).toBeGreaterThan(800);
            expect(c).toBeLessThan(1200);
        }
    });
});

describe("shuffle", () => {
    const items = ["a", "b", "c", "d", "e", "f", "g", "h", "i", "j", "k", "l"];

    it("元素不多不少，只是顺序变了", () => {
        const [result] = shuffle(items, seedFromString("s1"));
        expect([...result].sort()).toEqual(items);
        expect(result).not.toEqual(items);
    });
    it("不修改原数组", () => {
        const copy = [...items];
        shuffle(items, seedFromString("s1"));
        expect(items).toEqual(copy);
    });
    it("同一个种子洗出同一个顺序；不同种子洗出不同顺序", () => {
        expect(shuffle(items, 42)).toEqual(shuffle(items, 42));
        expect(shuffle(items, 42)[0]).not.toEqual(shuffle(items, 43)[0]);
    });
});
```

### 2.3 代码

新建 `packages/engine/src/aoi/rng.ts`。这一段是通用工具，不是游戏规则，直接照敲：

```ts
// 带种子的随机数。同一个种子永远得到同一串随机数，所以整局游戏可以重放。
// 随机数的"状态"是一个整数，存在 GameState.rng 里；每用一次就换成新的状态。

/** 把任意字符串变成种子（FNV-1a 哈希） */
export function seedFromString(seed: string): number {
    let h = 2166136261;
    for (let i = 0; i < seed.length; i++) {
        h ^= seed.charCodeAt(i);
        h = Math.imul(h, 16777619);
    }
    return h >>> 0;
}

/** 下一个 [0, 1) 之间的随机数。返回 [随机数, 新状态]。算法：mulberry32 */
export function nextRandom(rng: number): [number, number] {
    const next = (rng + 0x6d2b79f5) >>> 0;
    let t = next;
    t = Math.imul(t ^ (t >>> 15), t | 1);
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
    return [((t ^ (t >>> 14)) >>> 0) / 4294967296, next];
}

/** 0 ~ n-1 之间的随机整数。返回 [整数, 新状态] */
export function randomInt(rng: number, n: number): [number, number] {
    const [r, next] = nextRandom(rng);
    return [Math.floor(r * n), next];
}

/** 洗牌（Fisher-Yates 算法）。不修改原数组，返回 [新数组, 新状态] */
export function shuffle<T>(items: readonly T[], rng: number): [T[], number] {
    const result = [...items];
    let state = rng;
    for (let i = result.length - 1; i > 0; i--) {
        let j: number;
        [j, state] = randomInt(state, i + 1);
        [result[i], result[j]] = [result[j], result[i]];
    }
    return [result, state];
}
```

在 `index.ts` 末尾加一行：

```ts
export * from "./rng.js";
```

以后每写一个新文件，都要在 `index.ts` 加一行导出，前端和后端才能用到。

**几个函数的直观理解：**

- `seedFromString`：把任意字符串"搅拌"成一个整数。服务端开局时会用房间码加时间之类的字符串当种子（M2），测试里用 `"seed-1"` 这种好读的字符串。
- `nextRandom`：mulberry32 算法。几行位运算的作用是把输入的每一位充分打乱，你可以把它当成黑盒：输入一个整数，输出一个 0 到 1 之间的小数和下一个整数。
- `randomInt(rng, n)`：把 0 到 1 的小数乘以 `n` 再向下取整，得到 0 到 n−1 的整数。
- `shuffle`：**Fisher-Yates 洗牌**。想象一叠牌：从最后一个位置开始，每次从"还没定下来的牌"里随机抽一张放到这个位置，然后往前挪一位。每种排列出现的概率完全相等。

### 2.4 新语法

| TypeScript | Python | 说明 |
|---|---|---|
| `function shuffle<T>(items: readonly T[], …)` | `def shuffle(items: Sequence[T])` | **泛型**（generic）：`T` 是"任意类型"的占位符。传字符串数组进来，返回的就是字符串数组 |
| `readonly T[]` | `Sequence[T]` | 只读数组：函数保证不改它 |
| `[T[], number]` | `tuple[list[T], int]` | **元组**（tuple）：固定长度、每个位置类型固定的数组 |
| `[j, state] = randomInt(…)` | `j, state = random_int(…)` | 解构赋值（给已经声明过的变量） |
| `[a[i], a[j]] = [a[j], a[i]]` | `a[i], a[j] = a[j], a[i]` | 交换两个元素 |
| `x >>> 0` | `x & 0xFFFFFFFF` | 无符号右移 0 位，效果是把数变成 0 到 2³²−1 的整数 |
| `Math.imul(a, b)` | `(a * b) & 0xFFFFFFFF` | 32 位整数乘法（溢出的部分丢掉） |

### 2.5 读懂检查

1. `nextRandom` 为什么要把新状态返回出去，而不是在函数外面放一个变量、每次调用时改它？
2. `shuffle` 里为什么是 `randomInt(state, i + 1)`（从 0 到 i 里抽），而不是每次都从 0 到 `length - 1` 里抽？
3. 种子为什么用字符串，而不是直接用数字？

**答案**

1. 放在函数外面的变量是"隐藏的状态"：同一个函数调用两次结果不同，重放时也没法恢复到某个时刻。把状态显式传进传出，状态就能和 `GameState` 一起存下来、一起重放。
2. 第 `i` 个位置要从"还没定下来的牌"（第 0 到 i 张）里抽。每次都从全部牌里抽的写法看起来也能打乱，但不同排列出现的概率不相等，有的排列会多出现。
3. 服务端可以直接用有意义的字符串（房间码、时间）当种子，测试里也好读。字符串最终还是会被 `seedFromString` 变成数字。

2. 改回来，再把 `randomInt` 里的 `Math.floor` 改成 `Math.round`。哪个测试变红？为什么？

（第 2 题提示：`Math.round` 会让结果可能等于 `n`，而 0 和 n−1 两头各只分到半个区间。）

## 第 3 步：资源的加减（约 1 小时）

### 3.1 思路

`ResourceBundle`（一组资源）在 M1-1 就定义了，用来描述费用、收益。这一步写 4 个函数：

| 函数 | 做什么 |
|---|---|
| `addBundles(a, b)` | 两组资源相加（书按颜色分别相加） |
| `scaleBundle(b, times)` | 一组资源乘以次数（"转换 3 次"） |
| `gainResources(p, bundle)` | 玩家获得一组资源 |
| `payResources(p, bundle)` | 玩家支付一组资源，不够就返回 `null` |

获得和支付有几条规则：

- **学者有上限**：每人共 7 个学者，没拿到手的在**个人供应区**（`scholarsInSupply`）。获得学者时从供应区拿，供应区空了就拿不到；付出去的学者（例如学者换工具）回到供应区。
- **能量不是"个数"**：获得 N 点能量是按能量碗规则流动 N 步（M1-1 的 `gainPower`），支付是从碗 III 花（M1-1 的 `spendPower`）。
- **任选颜色的书**：获得时不直接加，返回 `bookChoices` 告诉调用者"还有几本要玩家选颜色"；支付时必须已经写明颜色。
- **铲子不是资源**：获得的铲子必须马上用来改造地形，不能存。所以 `gainResources` 遇到铲子直接报错，铲子由 `spades` 决策处理（M1-4）。

### 3.3 代码

新建 `packages/engine/src/aoi/resources.ts`：

```ts
import { gainPower, spendPower } from "./power.js";
import type { BookColor, PlayerState, ResourceBundle } from "./types.js";

/** 书以外的 6 种数量 */
const AMOUNT_KEYS = ["coins", "tools", "scholars", "vp", "power", "spades"] as const;

/** 两组资源相加。书按颜色分别相加；结果里不保留 0 */
export function addBundles(a: ResourceBundle, b: ResourceBundle): ResourceBundle {
    const result: ResourceBundle = {};
    for (const key of AMOUNT_KEYS) {
        const n = (a[key] ?? 0) + (b[key] ?? 0);
        if (n !== 0) result[key] = n;
    }
    const books: Partial<Record<BookColor, number>> = {};
    for (const source of [a.books ?? {}, b.books ?? {}]) {
        for (const [color, n] of Object.entries(source) as [BookColor, number][]) {
            books[color] = (books[color] ?? 0) + n;
        }
    }
    if (Object.keys(books).length > 0) result.books = books;
    return result;
}

/** 每一项都乘以 times，例如"转换 3 次" */
export function scaleBundle(b: ResourceBundle, times: number): ResourceBundle {
    let result: ResourceBundle = {};
    for (let i = 0; i < times; i++) result = addBundles(result, b);
    return result;
}

/**
 * 获得一组资源。
 * - 学者从个人供应区拿，供应区不够就能拿几个拿几个
 * - 能量按能量碗的规则流动
 * - 灰色的书（任选颜色）不直接加，算进 bookChoices，由调用的人生成 bookColor 决策
 */
export function gainResources(
    p: PlayerState,
    bundle: ResourceBundle,
): { player: PlayerState; bookChoices: number } {
    if (bundle.spades) throw new Error("铲子不能存起来，要用 spades 决策处理");
    const scholars = Math.min(bundle.scholars ?? 0, p.scholarsInSupply);
    const books = { ...p.books };
    let bookChoices = 0;
    for (const [color, n] of Object.entries(bundle.books ?? {}) as [BookColor, number][]) {
        if (color === "gray") bookChoices += n;
        else books[color] += n;
    }
    return {
        player: {
            ...p,
            coins: p.coins + (bundle.coins ?? 0),
            tools: p.tools + (bundle.tools ?? 0),
            vp: p.vp + (bundle.vp ?? 0),
            scholars: p.scholars + scholars,
            scholarsInSupply: p.scholarsInSupply - scholars,
            power: gainPower(p.power, bundle.power ?? 0).bowls,
            books,
        },
        bookChoices,
    };
}

/**
 * 支付一组资源，不够付时返回 null。
 * - 付出去的学者回到个人供应区
 * - 能量从碗 III 花
 * - 付书必须写清楚颜色，出现灰色说明调用的地方写错了
 */
export function payResources(p: PlayerState, bundle: ResourceBundle): PlayerState | null {
    if (bundle.spades) throw new Error("铲子不能用来付费");
    const coins = p.coins - (bundle.coins ?? 0);
    const tools = p.tools - (bundle.tools ?? 0);
    const vp = p.vp - (bundle.vp ?? 0);
    const scholars = p.scholars - (bundle.scholars ?? 0);
    if (coins < 0 || tools < 0 || vp < 0 || scholars < 0) return null;

    const power = spendPower(p.power, bundle.power ?? 0);
    if (power === null) return null;

    const books = { ...p.books };
    for (const [color, n] of Object.entries(bundle.books ?? {}) as [BookColor, number][]) {
        if (color === "gray") throw new Error("付书时要写清楚颜色");
        books[color] -= n;
        if (books[color] < 0) return null;
    }

    return {
        ...p,
        coins, tools, vp, scholars, power, books,
        scholarsInSupply: p.scholarsInSupply + (bundle.scholars ?? 0),
    };
}
```

### 3.4 新语法

| TypeScript | Python | 说明 |
|---|---|---|
| `["coins", …] as const` | | 告诉 TS：这是固定的几个字面量，不是普通的 `string[]`。这样 `a[key]` 才知道 `key` 一定是 `ResourceBundle` 的字段 |
| `Object.entries(obj)` | `obj.items()` | 得到 `[键, 值]` 对的数组 |
| `x as [BookColor, number][]` | `cast(...)` | **类型断言**（type assertion）：`Object.entries` 只知道键是 `string`，我们告诉 TS 这里的键其实是 `BookColor` |
| `a.books ?? {}` | `a.books or {}` | `??`：左边是 `undefined` 或 `null` 时用右边 |
| `{ ...p, coins: 5 }` | `{**p, "coins": 5}` | 复制对象再覆盖部分字段（M1-2 用过） |

关于类型断言：它是"我比编译器更清楚"的意思，TS 会照单全收，**不会**在运行时检查。所以只在确实知道的地方用，比如这里的书只可能是 `BookColor` 的几种颜色。

### 3.5 读懂检查

1. `addBundles` 为什么不保留加起来是 0 的项？
2. `gainResources` 里学者为什么要 `Math.min(…, p.scholarsInSupply)`，而能量不需要类似的处理？
3. `payResources` 先把所有扣减算完、检查完，最后才返回新对象。如果某一项不够，前面已经算好的扣减会不会"漏"到原来的玩家身上？

**答案**

1. 测试和比较时更干净：`{ coins: 0 }` 和 `{}` 意思一样，但 `toEqual` 会认为它们不同。统一不保留 0，就只有一种写法。
2. 学者是有限的实物，供应区没有就拿不到。能量的上限由碗决定，`gainPower` 本身已经处理了"碗满了流不动"的情况。
3. 不会。所有计算都是在新的局部变量上做的（`coins`、`books` 是复制出来的），原来的 `p` 从头到尾没被改过。返回 `null` 时，这些局部变量直接丢掉。

### 4.4 新语法

| TypeScript | 说明 |
|---|---|
| `Partial<PlanningDisplay>` | 把每个字段都变成可选。`display()` 的第二个参数只需要写和标准不同的字段 |
| `{ id, start: …, ...overrides }` | 先写默认值，最后展开 `overrides`：后写的覆盖先写的 |
| `Record<PlanningId, PlanningDisplay>` | 键必须是 7 种地形，**一个都不能少**；少写一个，TS 报错 |
| `Object.keys(FACTIONS) as FactionId[]` | `Object.keys` 只知道返回 `string[]`，这里断言成派系编号 |
| `` `rs-${i + 1}` `` | 模板字符串（template literal），相当于 Python 的 `f"rs-{i + 1}"` |
| `Array.from({ length: 17 }, (_, i) => i + 1)` | 生成 `[1, 2, …, 17]`，相当于 `list(range(1, 18))`；`_` 表示用不到的参数 |
| `.slice(1)` | 从下标 1 开始复制到末尾，相当于 `lst[1:]` |

### 4.5 读懂检查

1. `PLANNING_DISPLAYS` 的类型写成 `Record<PlanningId, PlanningDisplay>`。如果你漏写了 `lake: …` 这一行，会发生什么？如果类型写成 `Record<string, PlanningDisplay>` 呢？
2. 山脉的行会收入为什么写成 `[{ power: 1, coins: 3 }, ...STANDARD_INCOME.guild.slice(1)]`，而不是把 4 格全部重新写一遍？
3. 沙漠的开局铲子为什么单独放在 `startSpades`，不和工具、金币一起放进 `start`？
4. `display()` 里的 `...overrides` 如果写在最前面，会怎样？

**答案**

1. 前者：TypeScript 直接报错，说缺少 `lake` 属性。后者：编译通过，运行到 `PLANNING_DISPLAYS["lake"]` 时得到 `undefined`，然后在某个不相干的地方崩掉。这就是第 1 步把编号收紧成字面量联合类型的好处。
2. 只有第一格不同，后三格和标准一样。直接复用标准的后三格，以后标准数据要改，山脉会自动跟着改，不会出现两份数据对不上。
3. `start` 会交给 `gainResources` 发给玩家，而铲子不能存（第 3 步）。沙漠的铲子要等所有建筑放完再用，属于开局流程里的一个决策（第 7 步）。
4. 默认值写在后面，会把 `overrides` 里传进来的值盖掉，所有规划板都变成标准规划板。

## 第 5 步：收入（约 1 小时）

### 5.1 规则

每轮开始的**收入阶段**（Phase I），每个人同时拿收入，第 1 轮也有。收入来自：

1. **规划板**：固定收入，加上建筑建出去后露出来的格子（第 4 步）
2. **宫殿板块**：板块左边印着收入，**宫殿建好后**才算。固定组合开局时，宫殿板块是升级宫殿时才拿的；轮抽开局时，宫殿板块一开始就在手上，宫殿没建好之前不算收入
3. **手上的回合奖励板块**
4. **学科 9 级及以上**：学科展示板第 9 格旁边印着额外收入（银行 3 金币、法律 6 能量、工程 1 工具、医学 3 分）

还有三种收入来源以后再加：能力板块、创新板块（M3），以及奥马尔的派系能力（M3）。

拿收入时，学者从供应区拿、能量按碗流动、任选颜色的书要玩家选，这些第 3 步的 `gainResources` 都处理好了。

**怎么算"建了几座"**：不用去地图上数。规划板上每种建筑的总数是固定的（`BUILDINGS_TOTAL`），用总数减去还在规划板上的（`buildingsLeft`）就是建出去的数量。

```ts
import { BUILDINGS_TOTAL, DISCIPLINES, SCIENCE_INCOME, SCIENCE_INCOME_LEVEL } from "./constants.js";
import { BONUS_TILES } from "./content/bonusTiles.js";
import { PALACE_TILE_INCOME } from "./content/palaceTiles.js";
import { PLANNING_DISPLAYS } from "./content/planning.js";
import { addBundles, gainResources } from "./resources.js";
import type { BuildingType, GameState, PlayerState, ResourceBundle } from "./types.js";

const BUILDING_TYPES: readonly BuildingType[] = ["workshop", "guild", "school", "university", "palace"];

/**
 * 一位玩家这一轮的收入：
 *  1. 规划板上一直都有的收入
 *  2. 规划板上建筑建出去后露出来的格子
 *  3. 宫殿板块（宫殿建好后）
 *  4. 手上的回合奖励板块
 *  5. 学科 9 级及以上的额外收入
 * 能力板块、创新板块、派系能力的收入在 M3 加。
 */
export function incomeOf(p: PlayerState): ResourceBundle {
    const display = PLANNING_DISPLAYS[p.planning];
    let total = display.baseIncome;
    for (const type of BUILDING_TYPES) {
        const built = BUILDINGS_TOTAL[type] - p.buildingsLeft[type];
        for (let i = 0; i < built; i++) total = addBundles(total, display.income[type][i]);
    }
    // 轮抽开局时宫殿板块一开始就在手上，但宫殿建好了才有收入
    if (p.palaceTile !== null && p.buildingsLeft.palace === 0) {
        total = addBundles(total, PALACE_TILE_INCOME[p.palaceTile]);
    }
    if (p.bonusTile !== null) total = addBundles(total, BONUS_TILES[p.bonusTile].income);
    for (const d of DISCIPLINES) {
        if (p.science[d] >= SCIENCE_INCOME_LEVEL) total = addBundles(total, SCIENCE_INCOME[d]);
    }
    return total;
}

/** 收入阶段：所有玩家同时拿收入。要选颜色的书排进待决策队列 */
export function collectIncome(state: GameState): GameState {
    const pending = [...state.pending];
    const players = state.players.map((p) => {
        const { player, bookChoices } = gainResources(p, incomeOf(p));
        if (bookChoices > 0) {
            pending.push({ id: `income-${state.round}-${p.seat}`, seat: p.seat, kind: "bookColor", count: bookChoices });
        }
        return player;
    });
    return { ...state, players, pending };
}
```

1. "建 4 座工坊和建 5 座工坊收入一样"，代码里是哪里体现的？
2. 为什么用 `BUILDINGS_TOTAL - buildingsLeft` 算建了几座，而不是数地图上有几座工坊？有没有两者不一样的情况？

**答案**

1. 不在 `incomeOf` 里，而在数据里：`STANDARD_INCOME.workshop` 第 5 格是 `{}`。代码只负责"露出几格就加几格"，哪格有什么由数据决定。规则和数据分开，以后改数据不用改代码。

### 6.3 代码

新建 `packages/engine/src/aoi/convert.ts`：

```ts
import { gainResources, payResources, scaleBundle } from "./resources.js";
import type { ConversionId, Discipline, PlayerState, ResourceBundle } from "./types.js";

/** 每种转换做一次：付出什么、得到什么。灰色的书在转换时换成玩家指定的颜色 */
export const CONVERSIONS: Record<ConversionId, { cost: ResourceBundle; gain: ResourceBundle }> = {
    power5ToScholar: { cost: { power: 5 }, gain: { scholars: 1 } },
    power5ToBook: { cost: { power: 5 }, gain: { books: { gray: 1 } } },
    power3ToTool: { cost: { power: 3 }, gain: { tools: 1 } },
    power1ToCoin: { cost: { power: 1 }, gain: { coins: 1 } },
    scholarToTool: { cost: { scholars: 1 }, gain: { tools: 1 } },
    toolToCoin: { cost: { tools: 1 }, gain: { coins: 1 } },
    bookToCoin: { cost: { books: { gray: 1 } }, gain: { coins: 1 } },
};

/** 把灰色的书换成指定颜色 */
function paintBooks(b: ResourceBundle, color: Discipline): ResourceBundle {
    if (!b.books?.gray) return b;
    return { ...b, books: { [color]: b.books.gray } };
}

/**
 * 资源转换做 times 次。做不了时返回 null：
 * 次数不是正整数、需要颜色却没给、资源不够、学者供应区不够。
 */
export function convert(
    p: PlayerState,
    conversion: ConversionId,
    times: number,
    color?: Discipline,
): PlayerState | null {
    if (!Number.isInteger(times) || times < 1) return null;
    const needsColor = conversion === "power5ToBook" || conversion === "bookToCoin";
    if (needsColor && color === undefined) return null;
    if (conversion === "power5ToScholar" && p.scholarsInSupply < times) return null;

    let { cost, gain } = CONVERSIONS[conversion];
    if (color !== undefined) {
        cost = paintBooks(cost, color);
        gain = paintBooks(gain, color);
    }
    const paid = payResources(p, scaleBundle(cost, times));
    if (paid === null) return null;
    return gainResources(paid, scaleBundle(gain, times)).player;
}
```

### 6.4 新语法

| TypeScript | Python | 说明 |
|---|---|---|
| `color?: Discipline` | `color: Discipline \| None = None` | 可选参数，不传时是 `undefined` |
| `{ [color]: n }` | `{color: n}` | **计算属性名**（computed property name）：用变量的值当键。不加方括号的 `{ color: n }` 键就是字面上的 `"color"` |
| `b.books?.gray` | | `?.`：`b.books` 是 `undefined` 时整个表达式是 `undefined`，不会报错 |
| `let { cost, gain } = …` | `cost, gain = d["cost"], d["gain"]` | 对象解构；用 `let` 是因为后面要重新赋值 |

### 6.5 读懂检查

1. `power5ToScholar` 为什么要在付能量**之前**检查供应区够不够？只靠 `gainResources` 不行吗？
2. 转换的数据为什么写成一张表（`CONVERSIONS`），而不是在 `convert` 里写 7 个 `if`？
3. `times` 为什么要检查是不是正整数？前端不会发 1.5 次吧？

**答案**

1. `gainResources` 在供应区不够时会"能拿几个拿几个"。如果先付了 10 能量才发现只能拿到 1 个学者，玩家就白白亏了 5 能量。转换是玩家主动做的，做不到就应该整个拒绝。
2. 7 种转换的处理流程完全一样（付、得），只是数字不同。表格让"数据"和"流程"分开：加一种转换只加一行数据，规则书上的比率和代码里的表也一眼就能对上。
3. 服务器不能相信前端发来的任何东西。指令可能来自改过的前端、写错的脚本，或者有人手动发消息。0 次、负数次、1.5 次都要拒绝。

## 第 7 步：开局（约 4 小时，本课重点）

### 7.1 规则

开局分五段。第二段有两种方式，开房时在 `setupMode` 里选。

**一、摆公共版图**（`createGame` 一次做完）

- 12 个回合计分板块随机选 6 个放在第 1~6 轮；4 个终局回合计分板块随机选 1 个
- 6 个书本行动随机翻开 3 个
- 随机选一个**起始玩家**；从起始玩家开始按座位顺时针排行动顺序
- 再按开局方式摆出可选的东西（见第二段）

**二（方式一）、固定组合**（规则书的标准开局）

- 7 块规划板旁边各放 1 个随机派系、1 个随机回合奖励板块，组成 7 组。10 个回合奖励板块剩下的 3 个放到场上，各放 1 金币
- 宫殿板块：17 号每局都在，另外随机放"人数 + 1"个，升级宫殿时再从中选
- 从起始玩家**右手边**的人开始**逆时针**轮流选一组，也就是行动顺序倒过来，起始玩家最后选。没人选的组收回盒子

**二（方式二）、轮抽**

- 4 类东西分开摆：规划板"人数 + 1"块、派系"人数 + 1"个、宫殿板块"人数 + 1"个（不用 17 号）、回合奖励板块"人数 + 3"个
- 按**蛇形顺序**轮流拿：起始玩家开始顺时针一圈，再倒过来一圈，如此绕 4 圈（3 人局：1-2-3-3-2-1-1-2-3-3-2-1）
- 每次从**自己还没拿过的类别**里任选一样，所以绕完 4 圈每人每类正好各 1 个
- 拿完后，剩下的 3 个回合奖励板块放到场上，各放 1 金币；其他剩下的收回盒子
- 宫殿板块拿在手上，宫殿建好后才生效；以后升级宫殿时不用再选

**三、个人设置**：所有人选完后，每人：

- 20 分；12 个能量指示物按规划板分到碗 I 和碗 II；7 个学者、3 座桥放在供应区；建筑都放在规划板上
- 开局资源 = 规划板右上角 + 派系板块右侧
- 学科等级 = 规划板 + 派系上的学科图标个数

**四、放初始工坊**：按行动顺序每人在自己的家园地形上放 1 个工坊，再**倒过来**每人放 1 个。起始玩家放第一个和最后一个，行动顺序最后的人连放两个。初始工坊不花钱，也不会让邻居吸能。

**五、开局时要选的东西**：荒地的"1 本任选颜色的书"、蜥蜴的"任选学科 1 级 × 2"、沙漠的"放完建筑后 1 把铲子"。这些都需要玩家做选择，排进待决策队列，**怎么处理在 M1-4 写**（那一课要写推进学科、改造地形，正好用上）。

然后进入第 1 轮的收入阶段。

**这一课先不做的**：创新板块（M3）、能力板块（M1-4，升级学校时要用）、城市板块（M1-5）、回合计分板块的摆放限制（M1-5，例如"宫殿、大学计分的板块不能放在最后两轮"）、发明家、僧侣、奥马尔的开局特殊物品（M3）。

### 7.2 设计

**1. 选完之前，`players` 是空数组。** `PlayerState` 的每个字段都必须有值，派系、规划板、家园地形都要选完才知道。与其给这些字段填假值，不如等所有人选完、一次把所有玩家建好。选的过程记在 `setupSets[i].takenBy`（固定组合）或 `draft.picks`（轮抽）里。

**2. 两种方式，后半段共用。** 两种方式只有"怎么选"不一样；选完之后建立玩家用同一个 `createPlayer`，接下来放初始工坊用同一个 `startInitialWorkshops`。

```
固定组合：createGame → pickSet × 人数 ─────────┐
                                              ├→ createPlayer → 放初始工坊 → 开局结束
轮抽：    createGame → draftPick × 人数 × 4 ──┘
```

**3. 校验和执行分开。** 每种决策都有两个函数：

```ts
validatePickSet(state, seat, setId): RuleError | null   // 能不能这么选？不能的话为什么
applyPickSet(state, seat, setId): GameState             // 照着选（假设已经检查过）
```

这就是 M1-4 的 `validateMove` / `applyMove` 的小规模预演：服务器先校验，不通过就把 `RuleError` 回给前端；通过了才执行。分开写，执行的代码就不用到处夹着检查。

**4. 不存能算出来的东西。** "轮抽已经拿了几样"可以数 `picks` 里有几个不是 `null`；"已经放了几个初始工坊"可以从每人规划板上少了几座工坊算出来。下一步轮到谁，就用这个数去顺序表里查。如果另外存一个计数器，就要时刻保证它和真实情况一致，多一个出错的地方。

**5. 轮抽顺序是扩展点。** `draftOrder` 用 `switch` 按 `DraftOrder` 分情况，最后一个 `default` 里写 `const unhandled: never = …`（M1-2 前端用过的**穷尽检查**）。以后在 `DraftOrder` 类型里加一个新名字却忘了在这里加 `case`，类型检查会直接报错。

**6. `pending[0]` 就是现在在等的决定。** 开局是严格按顺序进行的，所以待决策队列里同一时间只有一个开局决策。

```ts
/**
 * 测试小工具：把随机摆出的 7 组换成固定的 7 组，这样每组选到什么是确定的。
 * 第 k 组（k = 0~6）的规划板按下面这个顺序。
 */
const FIXED: Omit<SetupSet, "id" | "takenBy">[] = [
    { planning: "wasteland", faction: "goblins", bonusTile: "coins6" },
    { planning: "swamp", faction: "navigators", bonusTile: "spadeAction" },
    { planning: "forest", faction: "blessed", bonusTile: "guildBuild" },
    { planning: "lake", faction: "lizards", bonusTile: "scholarSend" },
    { planning: "desert", faction: "moles", bonusTile: "levelAction" },
    { planning: "plains", faction: "philosophers", bonusTile: "schoolsPass" },
    { planning: "mountain", faction: "omar", bonusTile: "bridgeAction" },
];
function fixedGame(seed = "seed-1"): GameState {
    const game = createGame(OPTIONS, seed);
    const setupSets = FIXED.map((s, i) => ({ ...s, id: i, takenBy: null }));
    return { ...game, board: { ...game.board, setupSets } };
}

/** 按顺序帮每个人选组合：第 1 个选的人拿 picks[0]，以此类推 */
function pickAll(game: GameState, picks: number[]): GameState {
    let state = game;
    for (const setId of picks) {
        const seat = state.pending[0].seat;
        expect(validatePickSet(state, seat, setId)).toBeNull();
        state = applyPickSet(state, seat, setId);
    }
    return state;
}

const SPOTS: Record<Terrain, HexId[]> = {
    wasteland: ["A6", "C1"],
    swamp: ["A4", "A10"],
    forest: ["A1", "B4"],
    lake: ["A3", "A9"],
    desert: ["A12", "B7"],
    plains: ["A5", "A11"],
    mountain: ["A7", "B1"],

/** 按顺序帮每个人放初始工坊，每人用自己地形的第 1、2 个格子 */
function placeAll(game: GameState): GameState {
    let state = game;
    const used: Record<number, number> = {};
    while (state.phase === "setup") {
        const seat = state.pending[0].seat;
        const k = used[seat] ?? 0;
        used[seat] = k + 1;
        const hex = SPOTS[state.players[seat].homeTerrain][k];
        expect(validateInitialWorkshop(state, seat, hex)).toBeNull();
        state = applyInitialWorkshop(state, seat, hex);
    }
    return state;
}
```

测试里有几个小工具值得看一下：

- `fixedGame()`：固定组合开局摆出的 7 组是随机的，测试没法写死"第一个人拿到荒地"。所以先正常开局，再把 `setupSets` 换成固定的 7 组。
- `pickAll()`、`draftAll()`、`placeAll()`：自动按顺序帮每个人做决定，用来快速走到"选完"或"开局结束"。它们每一步都先调用 `validate…` 确认合法，所以这几个工具本身也在测试校验函数。

```ts
/**
 * 开一局新游戏。只有服务端调用；同一个 seed 永远得到同一局。
 * 人数或地图不对时直接抛错：这是服务端代码写错了，不是玩家操作的问题。
 */
export function createGame(options: SetupOptions, seed: string): GameState {
    const n = options.playerCount;
    if (!Number.isInteger(n) || n < 2 || n > 5) throw new Error(`人数必须是 2~5，收到 ${n}`);
    const mapDef = MAPS[options.mapId];
    if (mapDef === undefined) throw new Error(`没有这张地图：${options.mapId}`);

    // 随机数状态只在这个函数里面变；每抽一次，rng 就换成新的状态
    let rng = seedFromString(seed);
    function take<T>(items: readonly T[]): T[] {
        const [result, next] = shuffle(items, rng);
        rng = next;
        return result;
    }

    // 随机选起始玩家，然后按座位顺时针排行动顺序
    let start: number;
    [start, rng] = randomInt(rng, n);
    const turnOrder = Array.from({ length: n }, (_, i) => (start + i) % n);

    // 两种开局方式摆的东西不一样
    const otherPalaces = PALACE_TILE_IDS.filter((id) => id !== PALACE_TILE_ALWAYS);
    let setupSets: SetupSet[] = [];
    let draft: DraftPool | null = null;
    let bonusOnBoard: BonusTileId[] = [];
    let palaceTiles: PalaceTileId[] = [];
    if (options.setupMode.kind === "sets") {
        // 7 块规划板旁边各放 1 个随机派系和 1 个随机回合奖励板块；剩下 3 个回合奖励板块放到场上
        const factions = take(FACTION_IDS);
        const bonusTiles = take(BONUS_TILE_IDS);
        setupSets = PLANNING_IDS.map((planning, i): SetupSet => ({
            id: i, planning, faction: factions[i], bonusTile: bonusTiles[i], takenBy: null,
        }));
        bonusOnBoard = bonusTiles.slice(PLANNING_IDS.length);
        // 宫殿板块：17 号每局都在，另外随机放"人数 + 1"个，升级宫殿时再选
        palaceTiles = [PALACE_TILE_ALWAYS, ...take(otherPalaces).slice(0, n + 1)];
    } else {
        // 轮抽：4 类东西分开摆，每类"人数 + 几"个；宫殿板块不用 17 号
        draft = {
            planning: take(PLANNING_IDS).slice(0, n + DRAFT_EXTRA.planning),
            faction: take(FACTION_IDS).slice(0, n + DRAFT_EXTRA.faction),
            bonusTile: take(BONUS_TILE_IDS).slice(0, n + DRAFT_EXTRA.bonusTile),
            palaceTile: take(otherPalaces).slice(0, n + DRAFT_EXTRA.palaceTile),
            picks: Array.from({ length: n }, (): DraftPicks => ({
                planning: null, faction: null, bonusTile: null, palaceTile: null,
            })),
        };
    }

    const state: GameState = {
        contractVersion: CONTRACT_VERSION,
        version: 0,
        options,
        rng: 0, // 最后再填，等所有随机都抽完
        round: 0,
        phase: "setup",
        turnOrder,
        nextTurnOrder: [],
        turn: null,
        pending: [],
        hexes: initialHexes(parseMap(mapDef)),
        bridges: [],
        cities: [],
        players: [], // 所有人选完之后才建立
        board: {
            setupSets,
            draft,
            powerActionsUsed: [],
            bookActions: take(BOOK_ACTION_IDS).slice(0, 3),
            bookActionsUsed: [],
            scholarSpaces: {
                banking: [null, null, null, null],
                law: [null, null, null, null],
                engineering: [null, null, null, null],
                medicine: [null, null, null, null],
            },
            level12: { banking: null, law: null, engineering: null, medicine: null },
            roundScores: take(ROUND_SCORE_IDS).slice(0, 6),
            finalRoundScore: take(FINAL_ROUND_SCORE_IDS)[0],
            bonusTiles: bonusOnBoard.map((id) => ({ id, coins: 1 })),
            innovationsAvailable: [], // M3
            competenciesLeft: {},     // M1-4
            palaceTilesAvailable: palaceTiles,
            cityTilesLeft: {},        // M1-5
        },
        finalScores: null,
    };
    const first = options.setupMode.kind === "sets" ? nextPickSet(state) : nextDraftPick(state);
    return { ...state, rng, pending: [first!] };
}

// ---------- 方式一：固定组合 ----------

/** 选组合的顺序：从起始玩家右手边开始逆时针，也就是行动顺序倒过来 */
export function pickSetOrder(state: GameState): Seat[] {
    return [...state.turnOrder].reverse();
}

/** 下一个要选组合的决策；所有人都选完了返回 null */
function nextPickSet(state: GameState): Decision | null {
    const sets = state.board.setupSets;
    const taken = sets.filter((s) => s.takenBy !== null).length;
    const order = pickSetOrder(state);
    if (taken >= order.length) return null;
    const seat = order[taken];
    return {
        id: `pickSet-${seat}`,
        seat,
        kind: "pickSet",
        options: sets.filter((s) => s.takenBy === null).map((s) => s.id),
    };
}

export function validatePickSet(state: GameState, seat: Seat, setId: SetupSetId): RuleError | null {
    const d = state.pending[0];
    if (state.phase !== "setup" || d === undefined || d.kind !== "pickSet") return "wrong-phase";
    if (d.seat !== seat) return "not-your-decision";
    if (!d.options.includes(setId)) return "invalid-choice";
    return null;
}

/** 选一组。调用前先用 validatePickSet 检查 */
export function applyPickSet(state: GameState, seat: Seat, setId: SetupSetId): GameState {
    const setupSets = state.board.setupSets.map((s) => (s.id === setId ? { ...s, takenBy: seat } : s));
    const next: GameState = { ...state, board: { ...state.board, setupSets } };

    const decision = nextPickSet(next);
    if (decision !== null) return { ...next, pending: [decision] };

    // 所有人都选完了：按座位建立玩家，然后开始放初始工坊
    const players = Array.from({ length: state.options.playerCount }, (_, s) =>
        createPlayer(s, setupSets.find((set) => set.takenBy === s)!),
    );
    return startInitialWorkshops({ ...next, players });
}

// ---------- 方式二：轮抽 ----------

/** 轮抽的 4 类东西；每人每类拿 1 个，所以一共绕 4 圈 */
export const DRAFT_CATEGORIES: readonly DraftCategory[] = ["planning", "faction", "bonusTile", "palaceTile"];

/**
 * 轮抽每一步轮到谁。按开局设置里的 order 排；
 * 以后要加别的顺序，就在 DraftOrder 类型里加一个名字，再在这里加一个 case。
 */
export function draftOrder(state: GameState): Seat[] {
    const mode = state.options.setupMode;
    if (mode.kind !== "draft") return [];
    const t = state.turnOrder;
    switch (mode.order) {
        case "snake": {
            // 1-2-3, 3-2-1, 1-2-3, 3-2-1
            const result: Seat[] = [];
            for (let lap = 0; lap < DRAFT_CATEGORIES.length; lap++) {
                result.push(...(lap % 2 === 0 ? t : [...t].reverse()));
            }
            return result;
        }
        default: {
            const unhandled: never = mode.order;
            return unhandled;
        }
    }
}

/** 这个座位现在能拿的东西：自己还没拿过的类别里，池子中剩下的 */
export function draftOptions(pool: DraftPool, seat: Seat): DraftItem[] {
    const mine = pool.picks[seat];
    const items: DraftItem[] = [];
    if (mine.planning === null) for (const id of pool.planning) items.push({ category: "planning", id });
    if (mine.faction === null) for (const id of pool.faction) items.push({ category: "faction", id });
    if (mine.bonusTile === null) for (const id of pool.bonusTile) items.push({ category: "bonusTile", id });
    if (mine.palaceTile === null) for (const id of pool.palaceTile) items.push({ category: "palaceTile", id });
    return items;
}

/** 已经拿了几样：数每个人手上不是 null 的格子，不用另外记 */
function draftPicksMade(pool: DraftPool): number {
    return pool.picks.reduce((sum, p) => sum + DRAFT_CATEGORIES.filter((c) => p[c] !== null).length, 0);
}

function nextDraftPick(state: GameState): Decision | null {
    const pool = state.board.draft!;
    const order = draftOrder(state);
    const k = draftPicksMade(pool);
    if (k >= order.length) return null;
    const seat = order[k];
    return { id: `draftPick-${k}`, seat, kind: "draftPick", options: draftOptions(pool, seat) };
}

export function validateDraftPick(state: GameState, seat: Seat, item: DraftItem): RuleError | null {
    const d = state.pending[0];
    if (state.phase !== "setup" || d === undefined || d.kind !== "draftPick") return "wrong-phase";
    if (d.seat !== seat) return "not-your-decision";
    if (!d.options.some((o) => o.category === item.category && o.id === item.id)) return "invalid-choice";
    return null;
}

/** 把一样东西从池子里拿走，记到这个座位名下 */
function takeFromPool(pool: DraftPool, seat: Seat, item: DraftItem): DraftPool {
    const picks = [...pool.picks];
    const mine = picks[seat];
    switch (item.category) {
        case "planning":
            picks[seat] = { ...mine, planning: item.id };
            return { ...pool, picks, planning: pool.planning.filter((id) => id !== item.id) };
        case "faction":
            picks[seat] = { ...mine, faction: item.id };
            return { ...pool, picks, faction: pool.faction.filter((id) => id !== item.id) };
        case "bonusTile":
            picks[seat] = { ...mine, bonusTile: item.id };
            return { ...pool, picks, bonusTile: pool.bonusTile.filter((id) => id !== item.id) };
        case "palaceTile":
            picks[seat] = { ...mine, palaceTile: item.id };
            return { ...pool, picks, palaceTile: pool.palaceTile.filter((id) => id !== item.id) };
    }
}

/** 拿一样东西。调用前先用 validateDraftPick 检查 */
export function applyDraftPick(state: GameState, seat: Seat, item: DraftItem): GameState {
    const pool = takeFromPool(state.board.draft!, seat, item);
    const next: GameState = { ...state, board: { ...state.board, draft: pool } };

    const decision = nextDraftPick(next);
    if (decision !== null) return { ...next, pending: [decision] };

    // 所有人都拿完了：按座位建立玩家，宫殿板块先拿在手上（宫殿建好后才生效）
    const players = pool.picks.map((p, s) => ({
        ...createPlayer(s, { planning: p.planning!, faction: p.faction!, bonusTile: p.bonusTile! }),
        palaceTile: p.palaceTile,
    }));
    // 剩下的回合奖励板块放到场上，各放 1 金币；其他剩下的收回盒子
    const leftover: DraftPool = { ...pool, bonusTile: [] };
    const board = { ...next.board, draft: leftover, bonusTiles: pool.bonusTile.map((id) => ({ id, coins: 1 })) };
    return startInitialWorkshops({ ...next, board, players });
}

// ---------- 建立玩家 ----------

/** 建立一个玩家需要知道的三样东西 */
export type SetupChoice = Pick<SetupSet, "planning" | "faction" | "bonusTile">;

/** 根据选到的规划板、派系、回合奖励板块建立玩家：开局资源 = 规划板 + 派系 */
export function createPlayer(seat: Seat, choice: SetupChoice): PlayerState {
    const display = PLANNING_DISPLAYS[choice.planning];
    const faction = FACTIONS[choice.faction];
    const science = { banking: 0, law: 0, engineering: 0, medicine: 0 };
    for (const d of DISCIPLINES) {
        science[d] = (display.startScience[d] ?? 0) + (faction.startScience[d] ?? 0);
    }
    const blank: PlayerState = {
        seat,
        faction: choice.faction,
        planning: choice.planning,
        homeTerrain: choice.planning,
        vp: STARTING_VP,
        coins: 0,
        tools: 0,
        scholars: 0,
        scholarsInSupply: SCHOLARS_TOTAL,
        books: { banking: 0, law: 0, engineering: 0, medicine: 0 },
        power: STARTING_POWER[choice.planning],
        bridges: BRIDGES_TOTAL,
        sailing: display.startSailing,
        terraforming: 0,
        science,
        keys: 0,
        buildingsLeft: { ...BUILDINGS_TOTAL },
        palaceTile: null,
        innovations: [],
        competencies: [],
        cityTiles: [],
        bonusTile: choice.bonusTile,
        specialsUsed: [],
        passed: false,
    };

    return gainResources(blank, addBundles(display.start, faction.start)).player;
}

// ---------- 放初始工坊 ----------

/** 放初始工坊的顺序：按行动顺序每人放一个，再倒过来每人放一个 */
export function initialWorkshopOrder(state: GameState): Seat[] {
    return [...state.turnOrder, ...[...state.turnOrder].reverse()];
}

/** 已经放了几个初始工坊：从每人规划板上少了几座工坊算出来，不用另外记 */
function workshopsPlaced(state: GameState): number {
    return state.players.reduce((sum, p) => sum + BUILDINGS_TOTAL.workshop - p.buildingsLeft.workshop, 0);
}

function nextInitialWorkshop(state: GameState): Decision | null {
    const order = initialWorkshopOrder(state);
    const k = workshopsPlaced(state);
    if (k >= order.length) return null;
    return { id: `initialWorkshop-${k}`, seat: order[k], kind: "initialWorkshop" };
}

/** 两种开局方式选完后都从这里接着走：开始放初始工坊 */
function startInitialWorkshops(state: GameState): GameState {
    return { ...state, pending: [nextInitialWorkshop(state)!] };
}

export function validateInitialWorkshop(state: GameState, seat: Seat, hex: HexId): RuleError | null {
    const d = state.pending[0];
    if (state.phase !== "setup" || d === undefined || d.kind !== "initialWorkshop") return "wrong-phase";
    if (d.seat !== seat) return "not-your-decision";
    const h = state.hexes[hex];
    if (h === undefined) return "invalid-choice"; // 不存在的格子，或者是河流
    if (h.structure !== null) return "hex-occupied";
    if (h.terrain !== state.players[seat].homeTerrain) return "not-home-terrain";
    return null;
}

/** 放一个初始工坊（不花钱、不吸能）。调用前先用 validateInitialWorkshop 检查 */
export function applyInitialWorkshop(state: GameState, seat: Seat, hex: HexId): GameState {
    const hexes: Record<HexId, HexState> = {
        ...state.hexes,
        [hex]: {
            ...state.hexes[hex],
            structure: { owner: seat, type: "workshop", neutral: false, annex: false, city: null },
        },
    };
    const players = state.players.map((p) =>
        p.seat === seat ? { ...p, buildingsLeft: { ...p.buildingsLeft, workshop: p.buildingsLeft.workshop - 1 } } : p,
    );
    const next: GameState = { ...state, hexes, players };

    const decision = nextInitialWorkshop(next);
    if (decision !== null) return { ...next, pending: [decision] };
    return finishSetup(next);
}

/**
 * 工坊都放完了：开局设置结束，进入第 1 轮的收入阶段。
 * 开局时要自己选的东西排进待决策队列，按行动顺序：
 *  - 荒地：1 本任选颜色的书
 *  - 蜥蜴：任选学科前进 1 级，共 2 次
 *  - 沙漠：1 把免费铲子，不能顺带建工坊
 * 这些决策怎么处理在 M1-4 写。
 */
function finishSetup(state: GameState): GameState {
    const pending: Decision[] = [];
    for (const seat of state.turnOrder) {
        const p = state.players[seat];
        const display = PLANNING_DISPLAYS[p.planning];
        const faction = FACTIONS[p.faction];
        const books = (display.start.books?.gray ?? 0) + (faction.start.books?.gray ?? 0);
        if (books > 0) pending.push({ id: `setup-book-${seat}`, seat, kind: "bookColor", count: books });
        for (let i = 0; i < faction.scienceChoices; i++) {
            pending.push({ id: `setup-level-${seat}-${i}`, seat, kind: "scienceLevels", levels: 1 });
        }
        if (display.startSpades > 0) {
            pending.push({ id: `setup-spade-${seat}`, seat, kind: "spades", spades: display.startSpades, canBuild: false });
        }
    }
    return { ...state, round: 1, phase: "income", pending };
}
```

### 7.5 新语法

| TypeScript | 说明 |
|---|---|
| `function take<T>(…) { …; rng = next; … }` | 函数里面定义的函数（**闭包**，closure），可以读写外面的 `rng`。每次 `take` 一组东西，`rng` 就换成新状态 |
| `nextPickSet(state)!` | **非空断言**：告诉 TS"我保证这里不是 `null`"。刚开局时肯定有人要选，所以不可能是 `null` |
| `arr.reduce((sum, p) => sum + …, 0)` | 累加，相当于 Python 的 `sum(… for p in arr)` |
| `result.push(...t)` | 把数组 `t` 的元素一个个加进去，相当于 Python 的 `result.extend(t)` |
| `switch (item.category) { case "planning": … item.id … }` | **按可辨识联合分情况**：进了 `case "planning"`，TS 就知道 `item.id` 是规划板编号；进了 `case "palaceTile"`，就知道是数字 |
| `Pick<SetupSet, "planning" \| "faction" \| "bonusTile">` | 从一个类型里挑出几个字段组成新类型。`SetupSet` 和轮抽拿到的东西都能当 `SetupChoice` 用 |
| `{ ...state.hexes, [hex]: {…} }` | 复制整个字典，只替换 `hex` 这一格（计算属性名，第 6 步讲过） |
| `(planning, i): SetupSet => ({ … })` | 给箭头函数标上返回类型 |
| `for (;;) { … return …; }` | （测试里）不写条件的无限循环，靠里面的 `return` 跳出，相当于 Python 的 `while True:` |
| `Omit<SetupSet, "id" \| "takenBy">` | （测试里）去掉某些字段后的类型，和 `Pick` 相反 |

**为什么 `setupSets`、`hexes`、`leftover` 要专门标类型？** 引擎的代码也会被前端的类型检查读到，而前端的 `tsconfig.json` 没有打开 `strictNullChecks`。在那个设置下，对象里写的 `null` 或空数组 `[]` 会被推断成 `any`，然后报"隐式 any"的错。标上类型，TS 就知道 `takenBy: null` 的类型是 `Seat | null`。（M1-2 的 `never` 穷尽检查也是同一个原因。）

### 7.6 读懂检查

1. `createGame` 里的 `take` 函数修改了外面的变量 `rng`。`createGame` 还算"纯函数"吗？
2. 固定组合开局为什么要倒着选，让起始玩家最后选？
3. `takeFromPool` 为什么写成 4 个 `case`，而不是一行 `picks[seat] = { ...mine, [item.category]: item.id }`？
4. 以后想加一种轮抽顺序"每圈都顺时针"，要改哪几处？
5. 测试"同一个种子开出同一局"为什么重要？如果 `createGame` 里有一处用了 `Math.random()`，这个测试能发现吗？

**答案**

1. 算。纯函数指的是"同样的输入永远得到同样的输出，而且不改外面的东西"。`rng` 是 `createGame` 自己的局部变量，函数一结束就没了，外面看不到它被改过。函数内部用局部变量图方便，不影响对外的"纯"。
2. 起始玩家先手放工坊、先行动，占了便宜；让他最后选组合，只能拿别人挑剩的，算是平衡。
3. 一行的写法里，TS 不知道 `item.category` 和 `item.id` 是配对的（它只知道 `category` 是 4 类之一、`id` 是 4 种编号之一），没法保证不会把一个宫殿板块的数字写进 `planning` 字段，类型检查会放过错误或者直接报错。分成 4 个 `case` 后，每个分支里 TS 都确切知道 `id` 的类型，一个都不会配错。
4. 两处：`types.ts` 的 `DraftOrder` 加一个名字（例如 `"clockwise"`，这是接口变更，要走流程），`draftOrder` 的 `switch` 里加一个 `case`。只改了第一处、忘了第二处的话，`default` 里的 `never` 会让类型检查报错，提醒你还没写完。
5. M2 的断线恢复和撤销都靠"从开局重放所有指令"，开局本身必须能重现。能发现：`Math.random()` 每次结果不同，两次 `createGame` 摆出的组合几乎不可能一样，`toEqual` 会失败。
